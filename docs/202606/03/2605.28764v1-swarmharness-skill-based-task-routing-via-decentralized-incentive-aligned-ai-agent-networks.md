## 摘要
大量的计算资源（个人工作站上的GPU周期、空闲的推理服务器以及任务间隙的边缘设备）未被利用，原因是缺乏一种激励一致的协议，使得拥有者能够安全且有利地共享它们。现有方法要么需要可信的中心协调器（云市场），要么需要繁重的区块链基础设施（Golem、BrokerChain），要么完全缺乏激励层（BOINC、Petals）。我们提出SwarmHarness，这是一种去中心化协议，其中HarnessAPI技能节点无需任何中心化权威即可自组织成一个计算群体。SwarmHarness包含三个相互关联的组件：基于分布式哈希表（DHT）构建的SwarmRegistry，用于对等节点发现和能力公告；SwarmRouter，它通过一个基于能力、负载、延迟和信任的效用函数将任务分派给节点；以及SwarmCredit，一种激励机制，通过近似沙普利值为贡献节点分配计算信用奖励。节点通过服务任务赚取信用，并通过提交任务消耗信用；从不贡献的空闲节点会耗尽信用并失去路由优先级，从而形成一种自我调节的参与经济。随着节点向高回报技能专业化发展，且路由信号充当数字信息素，网络展现出类似于生物群体的涌现集体智能。除了计算共享，SwarmHarness还是自主分布式AI代理网络的基础原语，其中代理可以无需人工中介地雇佣计算、路由子任务和结算信用。

## Abstract
Vast quantities of compute (GPU cycles on personal workstations, idle inference servers, and edge devices between jobs) go unused because no incentive-aligned protocol exists for their owners to share them safely and profitably. Existing approaches either require a trusted central coordinator (cloud marketplaces), demand heavy blockchain infrastructure (Golem, BrokerChain), or lack an incentive layer entirely (BOINC, Petals). We propose SwarmHarness, a decentralised protocol in which HarnessAPI skill nodes self-organise into a compute swarm without any central authority. SwarmHarness has three interlocking components: a SwarmRegistry built on a Distributed Hash Table (DHT) for peer discovery and capability advertisement; a SwarmRouter that dispatches tasks to nodes using a utility function over capability, load, latency, and trust; and SwarmCredit, an incentive mechanism that attributes compute-credit rewards to contributing nodes via a Shapley-value approximation. Nodes earn credits by serving tasks and spend credits to submit them; idle nodes that never contribute drain credits and lose routing priority, creating a self-regulating participation economy. As nodes specialise toward high-reward skills and routing signals act as digital pheromones, the network exhibits emergent collective intelligence analogous to biological swarms. Beyond compute sharing, SwarmHarness is a foundational primitive for autonomous distributed AI agent networks in which agents hire compute, route subtasks, and settle credits without human intermediation.

## 2. 论文提出的方法论

### 核心思想
- 将 HarnessAPI 节点扩展为 SwarmNode，通过三个互锁组件实现去中心化、激励兼容的共享计算网络：
  1. **SwarmRegistry**：基于 DHT（类 Kademlia）的对等发现与能力公告。
  2. **SwarmRouter**：基于效用函数（能力匹配、负载、延迟、信任）的任务分派。
  3. **SwarmCredit**：基于近似沙普利值的信用分配机制，驱动自调节参与经济。

### 关键技术细节

#### 2.1 SwarmNode 定义
- 元组 `v = (Sv, rv, cv, τv)`，其中 `Sv` 为技能集合，`rv` 为资源向量（VRAM、CPU 等），`cv` 为信用余额，`τv` 为信任分数。
- 启动时：发现 SwarmRegistry → 发布能力公告（含节点 ID、技能、资源、信任分）→ 接受入站任务（基于 TLS，技能沙箱隔离）。

#### 2.2 SwarmRegistry（DHT）
- 键 = SHA256(技能名)，值 = 带 TTL 的节点广告列表。
- 节点每 `T_refresh` 秒刷新广告；超过 3×T_refresh 未刷新则被驱逐。
- 附加倒排索引（通过 gossip 协议传播）支持复杂查询（如“VRAM ≥ 8 GB”）。
- 三种引导机制（按优先级）：
  1. mDNS/本地网络（零配置）
  2. DNS 种子列表（多个独立运营者，社区治理）
  3. 显式对等节点列表（支持气隙或私有群）
- 种子节点仅入口，无特殊权威。

#### 2.3 SwarmRouter（效用函数路由）
- 给定任务 T 要求技能 s，候选集 C = {v1,...,vk}，评分函数：
  ```
  U(v, T) = w1·1[s∈Sv] + w2·(1−ℓv) + w3·(1−dv/d_max) + w4·τv
  ```
  其中 ℓv ∈ [0,1] 为负载分数，dv 为往返延迟，d_max 为延迟上限，τv 为信任分数，权重 w1..w4 和=1 可配置。
- 选择 argmax U(v,T) 分派；随机平局备用；失败时回退到次优候选。
- 支持冗余分派（如集成推理）至 Top-K 节点并合并结果。
- 多路由实例并发，提交者自行选择任何路由（路由本身注册为一种技能）。信用归属由提交者签名，恶意路由无法破坏账本。

#### 2.4 SwarmCredit 归属算法（Algorithm 1）
- **问题**：任务由节点联盟 N 执行；需分配信用 ∆c 满足效率（总和 = 信用池 C(T)）、公平（Shapley 值）、个体理性（∆c ≥ 0）。
- **Shapley 值近似**：通过 M 次随机排列采样，计算每个节点 i 的边际贡献均值 φi。
  - 特征函数 v(S) 衡量联盟 S 的任务质量（基于质量信号 q ∈ [0,1]）。
- **步骤**：
  1. M 次排列采样估计 φi。
  2. 归一化：若 Φ = Σmax(φi,0) > 0，则 ∆ci = (max(φi,0)/Φ) × C(T)；否则均匀分配。
  3. 更新信任分数：若 ∆ci > 0，τi ← τi + α(1−τi)；否则 τi ← τi − ατi。
  4. 从提交者扣除 C(T)。
- **复杂度**：精确计算 O(2^k)；采样近似标准误差 O(1/√M)，任务中 k 通常 ≤ 5（管道）或 ≤ 10（集成），M=100 即足够。

#### 2.5 冷启动与创世信用
- 新节点获得创世信用 c0（足够提交 k0 个任务），但需先成功服务至少一个经提交者签名的任务才能解锁（proof-of-contribution）。
- 阻止 Sybil 攻击：每个身份必须执行至少一个合法任务才能使用创世资金。
- 新提交者可获得一个免费任务提交权，之后必须通过运行节点或私下购买信用来获取。

#### 2.6 信用枯竭与信任衰减
- 未接受任务的节点信任分数按指数衰减：τv ← τv·(1−β)^(Δt/T0)（β 为衰减率，T0=24h）。
- τv → 0 导致路由优先级降低，最终失去所有流量，激励节点保持响应。

#### 2.7 数字信息素与涌现智能
- 高信用/高信任的节点吸引更多流量 → 正反馈循环。
- 负载接近满载时 ℓv 惩罚效用分数 → 负反馈防止垄断。
- 节点根据任务类型专业化，形成类似蚁群优化中的信息素蒸发机制，最终涌现负载分配和技能专业化。
