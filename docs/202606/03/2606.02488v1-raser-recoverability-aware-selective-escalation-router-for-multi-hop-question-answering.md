## 摘要
多跳问答系统通常对每个问题都使用昂贵的检索。它们可能会分解问题、执行多轮检索或在回答前通过桥接实体进行搜索。所有这些策略都依赖于重复的LLM调用来重写或分解问题，这增加了额外的令牌成本，并且在LLM预算紧张时不适用。然而，我们的分析表明，许多多跳问题已经通过一次性的单次RAG正确回答，因此对每个问题都执行额外的检索浪费了预算。我们引入了RASER（恢复性感知选择性升级路由器），这是一组基于单次RAG及其六个特征的廉价路由器。RASER-2决定是停止还是升级到额外检索动作PRUNE。RASER-3在单次RAG、PRUNE和迭代检索IRCoT之间进行选择，使用相同的特征，但增加了显式的成本-准确性权衡。两个路由器都不需要额外的LLM调用来做出决策。在六个LLM和三个多跳问答基准测试中，两个路由器在F1分数上与最新的其他基线相当，同时仅花费始终PRUNE方法41-49%的令牌，并且也少于迭代和分解检索基线。

## Abstract
Multi-hop question-answering systems often use expensive retrieval on every question. They may decompose the question, run several retrieval rounds, or search through bridge entities before answering. All of these strategies rely on repeated LLM calls to rewrite or decompose the question, which increases extra token cost, and it is not fitting when the LLM budget is tight. However, our analysis shows that lots of multi-hop questions are already answered correctly by a single one-shot RAG, so running an extra retrieval on every question wastes the budget. We introduce RASER (Recoverability-Aware Selective Escalation Router), a family of cheap routers built on one-shot RAG and six features from it. RASER-2 decides whether to stop or escalate to the extra-retrieval action PRUNE. RASER-3 chooses among one-shot RAG, PRUNE, and iterative retrieval IRCoT, using the same features but adding an explicit cost-accuracy trade-off. Neither router makes an extra LLM call to decide. Across six LLMs and three multi-hop QA benchmarks, both routers stay competitive with the other state-of-the-art (SOTA) baselines in F1 while spending only 41-49% of always-prune's tokens and also less than the iterative and decomposition retrieval baselines.

## 2. 论文提出的方法论

### 核心思想
- 构建一个廉价的路由器，基于单次 RAG 的输出（答案和 top-k 检索片段）提取六个特征，用梯度提升机（GBM）分类/回归模型预测“额外检索是否有用”，从而选择停止或升级到更昂贵的检索策略。
- 路由器 **不产生额外 LLM 调用**，所有特征均在单次 RAG 后直接计算。

### 关键技术细节
- **六个特征**（表 2）：
  1. `confidence`：基于规则的单次 RAG 答案置信度（从问题和答案类型推算）。
  2. `ans_len`：单次答案的单词数。
  3. `bridge_cues`：问题文本是否包含多跳语言模式（如“X of Y of Z”）。
  4. `score_gap`：检索得分第一与第五的差距（大差距表示检索清晰）。
  5. `score_top1`：最高检索得分。
  6. `qtype`：问题类型（实体/日期/是否/计数/其他）。
- **RASER-2**（二动作路由器）：训练一个 GBM 二分类器，预测是否 PRUNE（桥接检索）能比单次 RAG 提升 F1 > 0.1。若预测概率 ≥ 阈值 θ=0.2，则执行 PRUNE，否则返回单次答案。
- **RASER-3**（三动作路由器）：训练三个 GBM 回归器，分别预测单次 RAG、PRUNE、IRCoT* 的预期 F1。推理时用成本感知的 argmax 选择动作：`r* = argmax_r [f̂_r(s) - λ·c_r]`，其中 λ 为成本惩罚系数，c_r 为动作平均 token 成本。通过调节 λ 可控制预算，形成成本-准确率帕累托曲线。
- **PRUNE 动作**：四步流程——桥接实体提议（LLM 提取最多2个桥接实体）、分支检索、规则验证器丢弃弱分支、最终合成答案。
- **IRCoT* 动作**：迭代检索（最多3轮），每轮提取知识三元组，判断缺失信息后重新检索，最后合成答案。

### 算法流程（文字说明）
1. 对所有问题首先执行**一次单次 RAG**：检索 top-k 段落，LLM 给出草稿答案。
2. 从单次 RAG 结果计算六维特征向量。
3. 路由器（RASER-2 或 RASER-3）根据特征输出决策：
   - RASER-2：若桥接概率 ≥ θ，执行 PRUNE；否则输出单次答案。
   - RASER-3：三个回归器预测各动作 F1，减去 λ·c_r 后取最大值对应的动作。
4. 执行选中动作（若为 PRUNE 或 IRCoT*，则涉及额外检索和 LLM 调用），返回最终答案。

## 6. 论文的主要结论与发现

1. **恢复性分析揭示多数问题无需额外检索**：仅有 14-27% 的问题能从桥接检索中显著获益（F1 提升 ≥0.1），大量问题要么已被单次 RAG 正确回答，要么所有方法均无法改善。
2. **RASER-2 在保持精度的前提下大幅降低 token 成本**：与“始终 PRUNE”相比，F1 仅下降 0.026 以内，但 token 消耗仅为 39-57%（约 41-49%）。
3. **RASER-3 为需要迭代检索的场景提供成本可控的选择**：对小规模 LLM（如 Llama-3-8B）提升明显，可在 47-62% 的 token 预算下达到始终 IRCoT* 的 87-97% F1。
4. **特征重要性**：检索得分相关的特征（score_gap, score_top1）贡献最大（73%），其次为答案置信度和长度（24%），桥接词和问题类型作用很小。
5. **大模型依赖内部记忆**：GPT-OSS-120B 在 38% 的篡改答案问题上坚持原始答案，说明其依赖内部知识而非检索结果；小模型则更依赖检索，因此迭代检索对它们更有效。

## 7. 优点

- **轻量高效**：路由器仅需 6 个廉价特征，零额外 LLM 调用，训练使用 sklearn 标准 GBM，计算开销极小。
- **成本可控**：RASER-3 通过 λ 参数可显式控制 token 预算，用户可根据实际预算在精度和成本间权衡。
- **系统公平对比**：所有基线共享相同检索器、LLM、语料和分块方案，排除无关变量影响。
- **可解释性**：特征重要性分析揭示路由器决策主要依据检索可靠性，而非语义规则。
- **泛化性**：在 6 个不同规模、不同家族的 LLM 上均有效，且对三个多跳 QA 基准表现一致。

## 8. 不足与局限

- **基线简化**：IRCoT*、Self-Ask*、ChainRAG† 为简化版本，未完全复现原论文实现（如 KiRAG 的复杂推理组件），因此绝对数值不能直接与原文献对比。
- **评估规模小**：每个 (LLM, 数据集) 仅 200–500 测试问题，F1 可能存在统计噪声，结论的稳健性需更大规模验证。
- **大模型记忆偏差**：大 LLM 可能不依赖检索而凭参数化知识回答，使得 F1 不能准确反映检索效果，但作者专门做了内存检验并指出小模型更依赖检索。
- **阈值和预算依赖离线校准**：θ 和 λ 需在验证集上调优，跨域泛化性未充分验证。
- **未考虑多轮交互或长上下文场景**：路由器假设单次 RAG 已足够产生特征，对于需要多轮对话或极长上下文的问题可能不适用。
- **动作集合固定**：RASER-2 仅有停止/PRUNE 两动作，RASER-3 仅支持三种固定动作，未考虑更多检索策略或定制化动作组合的可能。
