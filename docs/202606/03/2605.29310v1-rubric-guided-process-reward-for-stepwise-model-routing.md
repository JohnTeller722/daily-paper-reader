## 摘要
逐步模型路由通过将每个推理步骤分配给合适的模型来提高大型推理模型（LRM）的效率。最近的方法将路由建模为序贯决策过程，并使用强化学习训练路由器。然而，尽管它们将路由建模为一个过程，但仍然使用结果奖励来监督路由器。这种奖励仅反映最终答案的正确性，无法评估中间路由决策，这可能削弱性能和泛化能力。为解决这一问题，我们提出RoRo，一种用于逐步模型路由的基于评分引导的过程奖励框架。RoRo首先收集多样化的路由轨迹，并基于结果、成本和过程质量构建偏好对。然后，它通过交替优化训练一个Rubricor生成查询特定的评估评分标准，并训练一个Judge根据该评分标准对路由轨迹进行评分。由此产生的过程奖励与结果奖励相结合，通过GRPO优化路由策略。在五个推理基准上的实验（包括同族和跨族设置）表明，RoRo始终优于强基线，并在准确性和成本权衡方面取得了更好的效果。

## Abstract
Stepwise model routing improves the efficiency of Large Reasoning Models (LRMs) by assigning each reasoning step to a suitable model. Recent methods formulate routing as a sequential decision process and train the router with reinforcement learning. However, although they model routing as a process, they still supervise the router with outcome rewards. Such rewards only reflect final answer correctness and fail to evaluate intermediate routing decisions, which can weaken performance and generalization. To address this gap, we propose RoRo, a rubric-guided process reward framework for stepwise model routing. RoRo first collects diverse routing trajectories and constructs preference pairs based on outcome, cost, and process quality. It then trains a Rubricor to generate a query-specific evaluation rubric and a Judge to score routing trajectories under this rubric through alternating optimization. The resulting process rewards are combined with outcome rewards to optimize the routing policy via GRPO. Experiments on five reasoning benchmarks under both same-family and cross-family settings show that RoRo consistently outperforms strong baselines and achieves better accuracy and cost trade-offs.

# 基于评分引导的逐步模型路由过程奖励（RoRo）——论文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：大型推理模型（LRM）在多步推理中表现优异，但推理链变长导致高昂的推理成本（延迟和计算开销）。逐步模型路由通过为每个推理步骤动态选择合适的模型（小型推理模型 SRM 或大型推理模型 LRM）来平衡性能与成本。现有方法（如 TRIM）将路由建模为序贯决策过程并用强化学习训练，但仅使用最终答案正确性作为结果奖励（outcome reward），忽略了中间路由决策的质量。
- **后果**：仅依赖结果奖励容易导致“欺骗性对齐”（deceptive alignment），即路由器虽能得到正确最终答案，但中间步骤的决策可能不合理，从而限制性能与泛化能力。作者通过初步实验（图1、图2）证明，附加简单的基于评分（rubric）的过程奖励就能持续提升性能。
- **整体含义**：逐步模型路由需要显式的**过程级奖励**来监督路由器优化，而评分（rubric）提供了可解释、可泛化的过程监督信号。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
提出 **RoRo**（Rubric-guided pRocess reward for stepwise mOdel routing）框架，通过训练一个**Rubricor**（评分生成器）和一个**Judge**（评分器）来为路由轨迹提供过程奖励，并与结果奖励和成本惩罚结合，使用 GRPO（Group Relative Policy Optimization）优化路由策略。

### 关键技术细节（三阶段）

#### 阶段1：路由偏好数据构建（Sec 3.1）
- **轨迹收集**：对每个训练查询，从六种路由策略收集轨迹池：SRM-only、LRM-only、随机路由、基于熵的路由、基于置信度的路由、仅结果奖励的路由器。这些策略覆盖多种行为与成本-性能权衡。
- **偏好对构建**：根据三个规则构建偏好对 ($\tau^+ \succ \tau^-$)：  
  - 结果偏好：最终答案正确者优先。  
  - 成本偏好：答案均正确时，LRM使用量少者优先。  
  - 过程偏好：结果和成本相似时，用种子评分（seed rubric）打分，高分者优先。

#### 阶段2：评分引导的过程奖励建模（Sec 3.2）
- **种子评分**：手动设计包含三个路由特定准则的初始评分，用于初始化 Judge 和提供初始过程偏好。
- **Judge 热身**：使用种子评分和 Bradley-Terry 目标函数训练 Judge。
- **交替优化**（多轮）：
  - **Phase 1（更新 Rubricor）**：冻结 Judge，Rubricor 根据轨迹池生成多个候选评分，经**验证门控**（validation gate）过滤（保留具有显著偏相关、高方差、低结果泄露的准则），用冻结 Judge 下的平均偏好边际奖励通过策略梯度更新 Rubricor。
  - **Phase 2（更新 Judge）**：冻结 Rubricor，生成验证后的评分，用所有偏好对重新训练 Judge。
- **过程奖励计算**：训练完成后，冻结 Rubricor 和 Judge。对每个查询的 GRPO rollout 组，Rubricor 生成评分，经验证后，Judge 为每条轨迹打分得 $R_{\text{process}}$。

#### 阶段3：过程感知的路由器优化（Sec 3.3）
- 用 GRPO 优化路由策略 $\pi_\theta$。综合奖励：  
  $$R_{\text{total}} = R_{\text{outcome}} - \lambda C + \beta R_{\text{process}}$$  
  其中 $R_{\text{outcome}}$ 为二值答案正确性，$C$ 为 LRM 生成 token 数，$\lambda$ 和 $\beta$ 为权重。
- 优势估计：在 rollout 组内对 $R_{\text{total}}$ 归一化得到 $A^{(k)}$，然后更新策略。

### 整体推理流程（Sec 3.4）
SRM 草拟候选步骤，路由器根据候选步骤和前缀摘要（含查询、历史动作、成本、不确定性信号）决定是接受（continue）还是再生（regenerate，由 LRM 重新生成）。重复直到生成完整答案或达到步数上限。

## 6. 主要结论与发现

1. **过程奖励是关键**：移除过程奖励使性能下降最大（表2），确认了 RoRo 的核心贡献。
2. **Rubricor 和 Judge 互补**：学习型 Rubricor 能发现超出人工种子评分的新维度；学习型 Judge 提供比直接评分更校准的过程奖励。
3. **验证门控有效**：过滤噪声和冗余准则，减少结果泄漏，提升奖励质量。
4. **成本-准确率前沿更优**：RoRo 在全部 FLOPs 范围内一致优于基线，尤其在低预算区域优势明显（图4）。
5. **难度区分能力更强**：RoRo 在困难问题上更频繁调用 LRM，在简单问题上更少，而 TRIM 分布更平坦（图5）。
6. **对不确定性信号鲁棒**：四种不确定性信号（平均熵、平均置信度、平均负对数似然、前3 token 熵）下性能波动小，表明框架不依赖特定信号。
7. **延迟加速可观**：以 Qwen3-14B 为 LRM，BA@20 时加速 2.516×；以 32B 为 LRM 时加速更大（BA@20 达 2.765×）。

- **创新性**：首次将过程奖励系统地引入逐步模型路由，填补了仅用结果奖励的监督空白。
- **方法设计合理**：三阶段框架清晰，偏好构造综合结果、成本和过程质量，交替优化结合统计验证保证了评分质量。

## 8. 不足与局限

- **依赖不确定性信号**：框架假设可获取 SRM 的 token 级概率分布，并非所有 API 都提供此信息（作者在 Limitations 部分指出）。
- **训练阶段成本较高**：Rubricor 和 Judge 的训练以及验证门控带来额外计算开销，尽管推理时不增加成本。
- **实验范围局限**：主要聚焦数学推理，未涵盖代码生成、科学问答等更广的推理任务（作者也提及需未来工作）。
