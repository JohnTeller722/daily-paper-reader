## 摘要
基于大型语言模型的多智能体系统通常围绕角色、流水线和轮次调度进行组织，而智能体之间传递的内容往往被设定为不受约束的自然语言。然而，这种自由形式的通信会迅速膨胀令牌使用量，消耗共享的上下文窗口，并最终影响系统性能和推理成本。我们分析了两种多智能体拓扑结构中的五种常见智能体间通信策略，发现没有一种固定策略是普遍最优的。相反，有效的智能体间消息始终保留下游智能体所需的以动作为中心的信息。基于此，我们提出了PACT（协议化动作-状态通信与传输），它把智能体间通信视为一个公共状态更新问题，并在每个原始智能体输出进入共享历史之前将其投影为紧凑的动作-状态记录。在不同的多智能体拓扑结构中，PACT始终改善了性能-成本权衡，以显著更少的令牌实现了相当或更强的任务性能。这种增益扩展到生产编码框架：PACT在每解决一个任务减少10%令牌的情况下提升了OpenHands的解决率，并且在将输入令牌减半的同时对SWE-agent保持解决率中性。我们的代码公开在https://github.com/iNLP-Lab/PACT。

## Abstract
Multi-agent systems (MAS) built on large language models are typically organized around roles, pipelines, and turn schedules, while the content that agents pass to one another is often left as unconstrained natural language. However, this free-form communication can rapidly inflate token usage, consume the shared context window, and ultimately affect both system performance and inference cost. We analyze five common inter-agent communication strategies across two MAS topologies, finding that no fixed strategy is universally optimal. Instead, effective inter-agent messages consistently preserve action-centered information needed by downstream agents. Building on this, we propose the PACT (Protocolized Action-state Communication and Transmission), which treats inter-agent communication as a public state-update problem and projects each raw agent output into a compact action-state record before it enters shared history. Across different MAS topologies, PACT consistently improves the performance-cost trade-off, achieving comparable or stronger task performance with substantially fewer tokens. The gains extend to production coding harnesses: PACT lifts OpenHands' resolve rate at -10% tokens-per-resolved, and is resolve-neutral on SWE-agent while halving input tokens. Our code is publicly available at https://github.com/iNLP-Lab/PACT.

- **问题**：在多智能体系统（MAS）中，智能体之间自由形式的自然语言通信导致 token 使用量急剧膨胀，共享上下文窗口被消耗，从而影响系统性能和推理成本。现有研究主要关注角色分配、轮次调度和工具分配，却忽略了一个关键设计维度：**智能体之间应该传递什么样的消息内容**。
- **动机**：通过对五种常见通信策略的诊断分析，发现没有一种策略是普遍最优的，有效的消息总是保留下游智能体所需的**以动作为中心的信息**。
- **整体含义**：本文首次系统性研究 MAS 中的消息内容设计，提出将通信视为公共状态更新问题，而非自由格式文本传递，从而在不牺牲性能的前提下大幅降低成本。

## 2. 论文提出的方法论

### 核心思想
将智能体间通信视为**公共状态更新问题**：每个非终端智能体的原始输出在进入共享历史之前，被投影（project）成一个紧凑的**动作-状态（action-state）记录**，仅包含下游智能体需要的接收方信息，排除中间推理和冗余内容。

### 关键技术细节
- **PACT 协议**：定义公共消息空间包含三个字段：
  - **ACTION**：发送者已执行的动作或要求下一个智能体执行的动作。
  - **STATE**：支撑该动作的证据、观察结果或环境反馈。
  - **RESULT**：动作的直接输出，如提取的事实、修正的方案或工具调用结果。
- **更新规则**：
  - 标准 MAS：\( H_{t+1} = H_t \oplus y_t \)（原始输出直接追加）。
  - PACT：\( H_{t+1} = H_t \oplus \Pi_{PACT}(y_t, o_t, r_t) \)，其中 \(\Pi_{PACT}\) 是发送端投影函数。
- **协议属性**：
  - 不约束智能体的私有计算（可自由进行内部推理）。
  - 与现有的 MAS 设计（角色结构、轮次调度等）正交，无需训练压缩器或修改模型。
  - 可适配不同场景：分裂证据交互中显式写出三个字段；流水线中可通过角色隐含部分动作信息，仅保留工件。

### 公式或算法流程（文字说明）
1. 每个智能体接收本地观察 \(o_t\) 和共享历史 \(H_t\)。
2. 智能体进行私有计算，产生原始输出 \(y_t\)。
3. 应用投影函数 \(\Pi_{PACT}\) 将 \(y_t\) 转换为只有 ACTION、STATE、RESULT 三个字段的紧凑消息。
4. 将该紧凑消息追加到共享历史 \(H_{t+1}\)。
5. 下一个智能体读取更新后的历史并继续。

## 3. 实验设计

### 使用的数据集/场景
- **Setting A（分裂证据交互）**：HotpotQA（多跳问答）、2WikiMultiHopQA（多跳推理）。每个智能体获得部分证据，需交换信息。
- **Setting B（顺序流水线）**：四个角色（Planner → Critic → Refiner → Solver）。使用 AIME2024、AIME2025（数学推理）、GPQA-Diamond（科学推理）、OpenBookQA（常识推理）。
- **编码框架**：SWE-bench Verified 上的 OpenHands（CodeActAgent）和 SWE-agent（解决真实 GitHub issue）。

### Benchmark 指标
- Setting A：token 重叠 F1 和总 tokens/问题。
- Setting B：准确率（Exact Match）和总 tokens/问题。
- 编码框架：解决率、平均完成 tokens/call、tokens/resolved。

### 对比方法
- **基线**：
  - **Full Content**：完整输出。
  - **Concise Generation**：非思考模式下的简短输出。
  - **Conclusion Only**：仅传递结论。
  - **Brief Summary**：要求智能体生成简短总结。
  - **Artifact Only**：仅传递角色工件（如计划、批评）。
  - **CoA**（Chain of Agents）：每个智能体只读前一个智能体的最新消息。
  - **TextMAS**：角色专业化智能体用自由自然语言协作，保留完整历史。
  - **Multi-Agent Debate**：多个智能体独立初答然后辩论。
- **PACT**：使用结构化的 action-state 记录。

## 6. 论文的主要结论与发现

1. **固定通信策略非普遍最优**：五种常见策略在不同设置下表现各异，没有一种在所有场景下同时达到高性能和低成本。
2. **PACT 显著改善性能-成本权衡**：在两种 MAS 设置下，PACT 平均减少 38.7% 的 token 使用，同时保持或提升任务性能（如在流水线中平均准确率优于 Multi-Agent Debate 且使用仅 19%~23% 的 tokens）。
3. **更强模型更善用紧凑通信**：随着模型规模增大，PACT 的 token 用量下降而性能提升，表明强模型不需要发送者的完整推理即可理解任务。
4. **编码框架实证有效**：
   - OpenHands：解决率从 19.40% 提升至 23.00%（+18 案例），每解决 token 减少 10.3%。
   - SWE-agent：输入 tokens 减少 50.4%，每解决 token 减少 47%，解决率基本持平（25.6%→24.2%）。

## 7. 优点

- **训练无关**：无需微调或改变模型，可直接作为推理时的通信协议应用于现有 MAS。
- **可移植性**：通过 LiteLLM 代理钩实现，可轻松插入 OpenHands、SWE-agent 等生产框架，无需修改框架代码。
- **基于诊断的合理设计**：通过系统实验发现有效信息类型（动作+状态+结果），而非随意选择。
- **区分公私计算**：私有推理过程保留，只压缩公共消息，不损害模型能力。
- **性能与成本双赢**：在多个设置下，不仅节省 token 还提升或持平性能，避免了常见压缩方法（如简单摘要）可能丢失关键信息的问题。

## 8. 不足与局限

- **场景覆盖有限**：仅测试了两种固定 MAS 拓扑（对称交互和顺序流水线）以及两种编码框架，未涉及动态路由、开放辩论、工具密集型规划等其他常见 MAS 结构。
- **模型通用性未验证**：所有实验基于 Qwen3 系列，未在 GPT、Claude 等闭源模型或 Mixtral 等其他开源模型上验证 PACT 的有效性。
- **字段设计的依赖性**：PACT 假设任务可以自然分解为 ACTION、STATE、RESULT 三个字段，对于某些需要传递复杂推理痕迹或柔性讨论的任务（如开放创意写作），该压缩可能过于激进。
- **未评估短交互场景**：论文承认 PACT 的优势在长历史累积的场景中最明显，对于短交互或消息不反复重用的架构，收益可能有限。
- **潜在偏差**：实验中使用的蒸馏证据分部（5个黄金段落+5个干扰项）和固定轮数均可能影响泛化性；真实多智能体场景中的干扰和不确定因素更多。
- **编码框架实验小幅性能波动**：SWE-agent 上解决率略降低（-1.4pp），尽管 token 大幅减少，但需进一步分析是否因压缩丢失关键调试信息。
