## 摘要
LLM智能体通过组合多种技能完成复杂任务，技能检索是智能体的前端环节。技能检索在监督层面上与传统文档检索存在根本差异：top-K联合正确性不仅取决于每个查询-技能对的语义相关性，还取决于检索到的技能能否协同完成给定查询下的任务。这种“技能兼容性”无法仅从独立相关性推导得出。然而，现有基于LLM的数据合成流程能够为“该查询下不应联合检索哪些技能”提供直接监督信号——即LLM自身的拒绝决策——而这一信号通常被视为低质量数据被丢弃。为弥补这一空白，我们提出了拒绝即资源检索器（R3）并构建了R3-Skill，一个面向实际智能体技能路由的双语（中英）技能检索基准。R3-Skill涵盖四种语言方向，查询措辞接近真实用户请求，并通过多专家交叉验证。在R3-Skill上，我们构建了一个两阶段检索系统（R3-Embedding + R3-Reranker），将技能兼容性作为显式训练信号。梯度分析表明，“推开”信号在双编码器中因双边平衡而被稀释，但在交叉编码器中充当无损分级排序监督——这促使将其置于交叉编码器阶段，两个数据集上的消融实验证实了这一点。R3-Embedding + R3-Reranker管道在R3-Skill上达到Hit@1=0.7714，NDCG@10=0.8327，Set-Compat=0.3525。数据集、训练代码和模型权重已作为开源资源发布，用于智能体技能路由。

## Abstract
LLM agents complete complex tasks by composing multiple skills, and skill retrieval is a front-end stage for agents. Skill retrieval differs fundamentally from traditional document retrieval at the supervision level: top-K joint correctness depends not only on the semantic relevance of each individual query-skill pair, but also on whether the skills retrieved together can collaborate to fulfill the task under the given query. Such "skill compatibility" cannot be derived from independent relevance alone. Yet existing LLM-based data synthesis pipelines can produce a direct supervision signal for "which skills should not be jointly retrieved under this query" -- namely the LLM's own rejection decisions -- and this signal is routinely discarded as low-quality data. To address this gap, we propose Reject-as-Resource Retriever (R3) and construct R3-Skill, a bilingual (Chinese-English) skill retrieval benchmark targeting realistic agent skill routing. R3-Skill spans four language directions, features query phrasings close to real user requests, and is verified through multi-expert cross-checking. On R3-Skill, we build a two-stage retrieval system (R3-Embedding + R3-Reranker) with skill compatibility as an explicit training signal. Gradient analysis shows that the "push-away" signal is diluted by bilateral balancing in the bi-encoder but acts as lossless graded ranking supervision in the cross-encoder -- motivating its placement at the cross-encoder stage, as confirmed by ablations on two datasets. The R3-Embedding + R3-Reranker pipeline attains Hit@1 = 0.7714, NDCG@10 = 0.8327 and Set-Compat = 0.3525 on R3-Skill. The dataset, training code and model weights are released as open source for agent skill routing.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题本质**：LLM 智能体（agent）通过组合多个“技能”（skill）来完成复杂任务。技能检索是智能体的前端环节，其目标是从大量技能库中选出与用户查询匹配的技能集合。与传统文档检索不同，技能检索不仅要求每个技能与查询语义相关（相关性），还要求被选出的多个技能之间能够协同工作（技能兼容性）。例如，同时检索“Terraform IaC”和“AUR Package Publish”可能在一种查询下合理，在另一种查询下却冲突。这种兼容性是查询依赖的，无法从独立的相关性信号中推导。

- **现状与空白**：现有 LLM 数据合成管道（如生成查询-技能对）通常丢弃 LLM 对技能组合的“拒绝”（SKIP）判断，认为那是低质量数据。然而，这些拒绝信号恰好提供了兼容性负监督。此外，现有技能检索数据集缺乏跨语言覆盖（仅英文），测试查询过于正式，偏离真实用户措辞。

- **研究意义**：该论文首次系统性地将技能兼容性纳入检索训练，并提出“将拒绝信号作为资源”的理念，构建了面向实际智能体技能路由的双语（中英）基准与两阶段检索器，填补了理论与数据空白。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
- **形式化分解**：将 top-K 联合正确概率分解为相关性因子与技能兼容性因子的乘积：  
  `Pr[S*_q ⊆ top-K | q] ≈ ∏ Pr[s ∈ top-K | q] * C(q, S*_q)`  
  其中 `C = 1` 对应传统文档检索的独立假设；`C < 1` 表示冲突，`C > 1` 表示协同。

- **拒绝即资源（Reject-as-Resource）**：将 LLM 在生成查询时对不合理技能组合的“SKIP”判决保存下来，作为训练中的负样本（兼容性标签），而不是丢弃。

### 关键技术细节
1. **R3-Skill 数据集构建**：
   - 从 GitHub 收集 95,212 个原始技能，去重后保留 10,246 个（中英文）。
   - 使用 BGE-M3 嵌入对技能聚类（K=40，合并为8个超域）。
   - 近邻硬约束采样：k=1 自由采样；k=2 要求两技能同子簇；k=3 要求同超域。
   - LLM（DeepSeek-V4-Pro）对每个技能组合给出 WRITE（生成查询）或 SKIP（拒绝），并记录拒绝原因（8类分类）。
   - 生成查询有6种风格（任务直述、场景描述等），覆盖4个语言方向（en2en, en2zh, zh2en, zh2zh）。
   - 测试集用 Qwen3-235B-A22B 生成，经多专家验证。

2. **两阶段检索系统 R3**：
   - **第一阶段 - R3-Embedding（双编码器）**：基于 Qwen3-Embedding-0.6B 微调，使用标准 InfoNCE 损失，候选池包含 GT 和 BM25 硬负例。**不注入 SKIP 信号**。
   - **第二阶段 - R3-Reranker（交叉编码器）**：基于 Qwen3-Reranker-0.6B 微调，候选池由 GT、SKIP 合作伙伴和 R3-Embedding 召回的前20名组成（固定10个候选）。采用分级 ListNet 损失：标签分配为 GT=3，SKIP=1，其他=0。SKIP 信号在此作为中间级别调整排序。

### 为什么 SKIP 放在交叉编码器而非双编码器
- **梯度分析（附录 B）**：在双编码器中，同一技能嵌入同时接收来自不同查询的“推开”梯度（作为 SKIP）和“拉近”梯度（作为 GT），导致双边平衡，推开信号被稀释，无效。在交叉编码器中，每个查询-技能对独立评分，推开信号可无损用作排序监督。实验证实了这一选择。

## 6. 主要结论与发现

1. **技能兼容性是核心差距**：单技能相关性高的组合在联合检索时可能冲突，Set-Compat 指标在嵌入阶段仅为 0.2218，说明传统检索方法在技能集合完整性上不足。
2. **SKIP 信号有效但仅在交叉编码器**：在双编码器中注入 SKIP 导致性能微降（+0.31pp 等），而在交叉编码器中使用分级标签显著提升 Hit@1 (+4.83pp)、NDCG@10 (+2.18pp) 和 Set-Compat (+3.37pp)。
3. **两阶段系统达到最优**：R3-Embedding + R3-Reranker 在 R3-Skill 上实现 Hit@1=0.7714，NDCG@10=0.8327，Set-Compat=0.3525。在 SkillRet 上接近或超过公开基线。
4. **跨语言挑战**：en2zh 是最困难的方向（Set-Compat 嵌入仅14.87），重排后提升显著（+13.34pp），但仍有差距。中文技能数量稀少（246个），是主要瓶颈。

## 7. 优点

- **理论创新**：首次将技能兼容性形式化为概率分解中的乘法因子，并论证其查询依赖性，区别于传统文档检索。
- **数据创新**：“拒绝即资源”理念回收了被浪费的监督信号，构建了包含拒绝原因分类的大规模双语技能检索数据集。
- **方法设计**：梯度分析指导了 SKIP 信号的最优放置（交叉编码器），避免双编码器中的双边平衡问题，理论分析与实验一致。
- **评估指标**：提出 Set-Compat 专门衡量多技能集合的完整检索能力，更贴合实际路由需求。
- **开源贡献**：公开了数据集、代码和模型权重，促进社区发展。

## 8. 不足与局限

- **中文技能覆盖不足**：仅 246 个中文技能，反映公共生态系统现状，限制了跨语言能力评估。

- **未评估下游任务完成率**：仅测评检索命中率，但 SRA-Bench 等已表明检索命中不一定转化为任务完成。缺少端到端 Agent 流程验证。
- **重排池大小固定**：仅用 top-20，未探索更大 pool（如 50/100）时 Set-Compat 能否继续提升。
- **缺乏更多维度的消融**：如按拒绝原因分类、按近邻几何距离、按多技能个数（k=1/2/3）的压力测试未做，留待未来。
