## 摘要
经典查询优化搜索在代数上等价的计划，这些计划仅在成本上有所不同。一旦引入基于大语言模型（LLM）的算子，这一假设便被打破：其放置、排序和粒度共同决定了美元成本和答案质量，而替代方案中的正确选择通常只有在运行时才能显现。我们将这一设定形式化为代理查询执行——一种将基于代理的规划与执行交织的查询执行范式，其中代理工作流优化类比于经典查询优化。随后，我们提出EnumGRPO，一种用于该设定的自我改进型优化器。在学习阶段，EnumGRPO枚举执行范式、算子类型、算子放置、选择性范围及投影宽度等决策上的查询计划，然后通过上下文强化学习将质量-成本反馈提炼为可复用的规划启发式。在SWAN的四个数据库中，EnumGRPO在LLM算子成本为每条查询0.011美元的情况下实现了35.4%的执行准确率，相较于混合查询基线降低了约317倍的成本，同时在答案准确率上相对提升了18%。

## Abstract
Classical query optimization searches over algebraically equivalent plans that differ only in cost. This assumption breaks once LLM-backed operators enter the picture: their placement, ordering, and granularity jointly determine both dollar cost and answer quality, and the right choice among the alternatives is often revealed only at runtime. We formalize this setting as agentic query execution, a query execution paradigm in which agent-based planning is interleaved with execution, and agent workflow optimization becomes the analogue of classical query optimization. We then present EnumGRPO, a self-improving optimizer for this setting. During a learning stage, EnumGRPO enumerates query plans over decisions such as execution paradigm, operator type, operator placement, selectivity scope, and projection width, then distills quality-cost feedback into reusable planning heuristics via in-context reinforcement learning. Across four databases in SWAN, EnumGRPO achieves 35.4% execution accuracy at $0.011 per query in LLM-operator cost, a ~317x cost reduction over the hybrid query baseline with an 18% relative improvement in answer accuracy.

- **核心问题**：如何为混合了SQL与LLM算子的代理查询执行进行优化，使其能在运行时动态选择工作流结构，平衡答案质量与LLM使用成本？

## 2. 方法论：核心思想、关键技术细节、公式或算法流程
### 2.1 核心思想
- 提出**EnumGRPO**，一个自我改进的优化器。它在学习阶段显式枚举基于五种正交规划轴（执行范式、算子类型、算子放置、选择性范围、投影宽度）的不同候选工作流，执行并评分，然后通过**上下文强化学习（In‑Context Reinforcement Learning, ICRL）**将质量‑成本反馈提炼为可复用的规划启发式，存储在**经验池**ε中。查询时，Agent直接利用这些启发式进行步骤式决策，无需再次枚举。
- **关键设计**：不更新LLM模型参数（权重冻结），所有策略改进通过修改Agent提示中的经验池ε实现。这使得优化器可迁移到不同LLM后端（包括闭源API），无需重训。

### 2.2 关键技术细节
1. **规划空间（Plan Space）**：识别五个正交决策轴，每个都有经典优化类比：
   - **执行范式**：数据驱动（per‑tuple LLM调用） vs. 代码驱动（合成SQL规则，O(1) LLM调用）。
   - **算子类型**：标量（逐行处理） vs. 聚合（一次处理整个集合）。
   - **算子放置**：预聚合 vs. 后聚合（类似谓词下推）。
   - **选择性范围**：全部 vs. 目标（通过SQL预过滤缩小LLM输入）。
   - **投影宽度**：窄（仅必需列） vs. 宽（包括上下文列）。

2. **EnumGRPO算法流程（学习阶段）**：
   - **计划枚举**：对每个查询，使用LLM生成N个不同的轴赋值（保证多样性），注入Agent提示作为软推荐。
   - **并行执行**：对每个轴赋值独立执行工作流，得到轨迹τ。
   - **多目标奖励**：组合三个粒度的质量分数（精确匹配EX、元组级F1、细胞级F1）与归一化的成本（token数和步骤数），公式：
     - 质量分数 r = w_ex·EX + w_tuple·TupleF1 + w_cell·CellF1
     - 成本排名 ρ = w_token·归一化token + w_step·归一化步骤
     - 最终奖励 r* = r − w_cost·ρ
   - **组相对优势**：对同一查询的N个rollout，计算奖励的z‑score作为优势A_i，并分解为效用优势Utili和成本优势Costi。
   - **经验蒸馏**：四阶段LLM管道：
     1. 轨迹摘要（压缩行为描述）
     2. 对比分析（对比高/低优势反例，提炼可推广指南）
     3. 池更新（判断提案是否新增、更新或删除）
     4. 批量整合（去重，保持全局一致性）
   - 更新后的经验池ε追加到Agent系统提示，用于下一批次。

3. **查询时执行**：
   - 将学到的经验池ε直接注入Agent系统提示。
   - Agent逐步执行，使用ε指导决策（如优先代码驱动、窄投影等），无需枚举。

### 2.3 公式与算法（文字描述）
- **目标函数**：最大化期望轨迹奖励：max J(π) = E_{τ~π}[U(y) − λ Σ c(s_t, a_t)]，其中U为输出质量，c为累积成本。
- **上下文强化学习目标**：max_{c⊆C} J(π_{θ,c})，通过选择最优提示上下文c优化策略，不更新模型参数θ。
- **GRPO机制**：在每个查询的rollout组内，奖励进行z‑score归一化，产生正负对比信号，精准归因结构决策差异。

## 7. 优点
1. **问题新颖**：正式定义了代理查询执行中的优化问题，将经典优化推广到质量‑成本联合优化的复杂场景。
2. **无需微调LLM**：通过上下文强化学习和经验池蒸馏实现策略改进，避免梯度更新，兼容闭源API和模型升级。
3. **结构化规划空间**：五个正交轴提供了清晰的分析框架，易于理解和扩展。
4. **多粒度奖励**：结合EX、元组F1、细胞F1，缓解稀疏奖励问题，更好引导学习。
5. **组相对优势**：通过组内z‑score归一化，消除查询难度差异，将推理信号聚焦于结构决策。
6. **可迁移性**：实验显示经验池可跨数据库泛化，且成本降低显著。
7. **实验全面**：多数据库、可扩展性、消融分析、成本收益分析，结果可靠。

## 8. 不足与局限
1. **准确率仍较低**：最高35.4%，仍有大量查询无法正确回答，可能受限于底层LLM能力或规划空间覆盖不足。
2. **仅评估SWAN基准**：虽为专门设计的超越数据库问题基准，但可能不代表所有混合查询场景；需要更多现实应用验证。
3. **学习阶段成本**：尽管可摊销，但初始学习需$41.2和8.4小时，对一次性或小规模部署可能不划算。
4. **经验池维护**：经验池一旦固定，数据分布或查询模式变化后可能失效；论文未讨论持续学习或池刷新机制。
5. **仅使用单一LLM骨干（Claude）**：虽声称可迁移，但未测试其他模型（如GPT‑4、Llama等）；启发式在不同模型上的适用性未知。
6. **可扩展性实验有限**：仅缩放主表，未测试多表连接或更复杂SQL场景；部分数据库无法下采样（需要保留金答案行），存在偏差。
7. **代理执行超时限制**：30步骤/30分钟可能截断某些复杂查询的尝试，影响准确率上限。
8. **未对比任何自适应查询优化基线**（如Eddies、SkinnerDB等）或更近期的LLM‑增强优化器（如Palimpzest）。
