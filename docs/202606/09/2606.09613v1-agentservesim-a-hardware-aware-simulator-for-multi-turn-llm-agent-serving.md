## 摘要
多轮LLM智能体将模型调用与外部工具调用交织在一起，将服务从无状态请求处理转变为有状态程序执行。服务这些工作负载需要利用程序级上下文的调度、KV缓存管理和路由策略，包括轮次依赖、工具引入的空档和可重用的KV状态。直接在真实系统上评估此类策略成本高昂，因为每个设计点可能需要专用的加速器时间，涉及到达率、模型规模、服务实例数量和内存层次结构。模拟提供了一种可扩展的替代方案，但现有的LLM服务模拟器针对无状态请求级工作负载，因此忽略了智能体服务的核心动态：多轮程序执行、跨轮缓存局部性以及工具空档期间的KV缓存驻留。我们提出了AGENTSERVESIM，一个面向多轮LLM智能体服务的硬件感知模拟器。AGENTSERVESIM通过可组合模块以程序粒度评估服务策略：程序编排器保留程序标识和轮次顺序，工具模拟器实现工具引入的空档，会话感知路由器维护程序到实例的亲和性以实现缓存感知调度，KV驻留模型跟踪策略定义的KV在HBM、主机DRAM/CXL和驱逐中的放置。在真实服务部署和硬件配置上，AGENTSERVESIM在关键性能指标上以6%以内的误差复现了真实系统行为，同时完全在商用CPU上运行。这些结果表明，AGENTSERVESIM能够无需在昂贵的加速器上详尽部署即可进行受控、可重复的智能体服务策略探索。

## Abstract
Multi-turn LLM agents interleave model calls with external tool invocations, shifting serving from stateless request processing to stateful program execution. Serving these workloads requires scheduling, KV-cache management, and routing policies that use program-level context, including turn dependencies, tool-induced gaps, and reusable KV state. Evaluating such policies directly on real systems is costly, since each design point may require dedicated accelerator time across arrival rates, model scales, serving-instance counts, and memory hierarchies. Simulation offers a scalable alternative, but existing LLM serving simulators target stateless request-level workloads and therefore omit the core dynamics of agent serving: multi-turn program execution, cross-turn cache locality, and KV-cache residency during tool gaps. We present AGENTSERVESIM, a hardware-aware simulator for multi-turn LLM agent serving. AGENTSERVESIM evaluates serving policies at program granularity through composable modules: a Program Orchestrator preserves program identity and turn order, a Tool Simulator materializes tool-induced gaps, a Session-Aware Router maintains program-to-instance affinity for cache-aware dispatch, and a KV Residency Model tracks policy-defined KV placement across HBM, host DRAM/CXL, and eviction. Across real serving deployments and hardware configurations, AGENTSERVESIM reproduces real-system behavior within 6% error across key performance metrics while running entirely on commodity CPUs. These results show that AGENTSERVESIM enables controlled, repeatable exploration of agent-serving policies without requiring exhaustive deployment on costly accelerators.

# AGENTSERVESIM 论文详细总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：多轮 LLM 智能体系统（如 Cursor、Claude Code、Codex、Web 搜索 agent、长期规划 agent）逐渐取代传统单轮聊天。这些系统是**有状态程序**，将多次 LLM 调用与外部工具调用交织组合。工具调用时长从毫秒（cat）到分钟（pytest）不等，用户感知指标是**程序作业完成时间（JCT）**，而非单次 LLM 调用的延迟。
- **核心问题**：现有的 LLM 服务模拟器（如 Vidur、APEX、LLMServingSim）仅针对**无状态请求**，缺乏程序标识、工具调用间隙、跨轮 KV 重用等关键抽象，无法评估智能体专用的调度、KV 缓存管理和路由策略。
- **研究目标**：构建一个**硬件感知**、**程序粒度**的模拟器，能够忠实复现多轮 agent 服务的性能，支持大规模设计空间探索，且仅需普通 CPU 运行。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将**代理程序**而非单个 LLM 调用作为执行单元，通过可组合模块在模拟中保留程序标识、轮次依赖、工具间隙、路由局部性和跨轮 KV 驻留。
- **关键技术模块**：

  - **Program Orchestrator（程序编排器）**：维护每个程序的状态机，含四个事件（New Turn、Turn Complete、Invoke Tool、Tool Complete），控制下一轮的释放必须等待前一轮及其工具间隙完成，从而保证程序 JCT 的正确模拟。
  - **Tool Simulator（工具模拟器）**：支持两种模式——**回放模式**（使用捕捉到的真实工具时长）和**生成模式**（基于工具名称从分布中采样），注入工具间隙期间不占用 GPU 状态，时长由 KV 驻留模型管理。
  - **Session-Aware Router（会话感知路由器）**：维护程序到 MSG（模型服务组）的亲和性表，默认将后续轮次路由到同一实例；若实例过载，允许等待、迁移（支付模拟 KV 传输成本）或重预填充，使路由决策体现缓存局部性代价。
  - **Program-Aware Batch Scheduler（程序感知批调度器）**：以程序标识为键，暴露程序级状态（已获得服务、历史）给可插拔策略钩子，支持请求级 FCFS、程序级 FCFS、已获得服务优先级、中断感知等变体，共享同一准入和连续批处理逻辑。
  - **KV Residency Model（KV 驻留模型）**：基于 RadixAttention 前缀缓存，为每个程序的 KV 节点标注策略定义的截止时间；支持 HBM、主机 DRAM/CXL 和驱逐三层次，驱逐遵循截止时间但可在内存压力下覆盖（记录 TTL 缺失事件）；中断感知策略可根据预测间隙与交换恢复成本决定是否交换到主机。
- **运行流程**：
  1. 初始化：为每个 LLM 构建 MSG，绑定设备，安装策略。
  2. 运行循环：程序编排器 → 工具模拟器 → 会话感知路由器 → 程序感知批调度器 → 在 MSG 内生成操作图 → 操作映射器和调度器（继承 LLMServingSim 2.0）→ 改进的 ASTRA-sim/Chakra 后端执行图（考虑设备间通信、内存层次）。
  3. 一轮完成后，KV 驻留模型决定 KV 状态保留、交换或丢弃。

## 3. 实验设计

- **数据集/场景**：使用 **SWE-Bench Verified** 真实 agent 追踪（通过运行 mini-swe-agent 在 Qwen3.6 上收集），含 50 个程序，每程序平均约 42 轮，总 token 数 356k，工具时长分布长尾（均值为 1161ms，标准差 4125ms）。
- **Benchmark**：对比四个策略在真实部署与模拟器上的性能差异。四个策略分别为：
  - vLLM-FCFS：请求级 FCFS，轮结束即驱逐 KV。
  - Continuum：程序级 FCFS 加成本模型引导的 KV 保留。
  - Autellix：程序级已获得服务调度。
  - InferCept：中断感知 KV 管理（在工具间隙决定丢弃、保留或交换 KV）。
- **硬件平台**：三款 NVIDIA GPU：RTX 3090 (24GB GDDR6X)、H100-SXM (80GB HBM3)、B200 (180GB HBM3e)。每个节点使用单 Slurm 分配，配 64-128GB 主机 DRAM 和 8 CPU 核心。真实系统使用 vLLM。
- **模拟器参数化**：针对各 (设备，模型) 对收集操作符级延迟 profile，主机 DRAM 和 CXL 带宽作为静态参数。
- **对比方法**：未直接对比其它模拟器（因缺乏 agent 能力），而是将模拟器输出与真实系统在同一策略下的输出进行对比。

## 6. 论文的主要结论与发现

- **模拟精度**：AGENTSERVESIM 在 JCT、吞吐量等指标上与真实部署匹配至 6% 以内，且保留策略相对排序。
- **会话亲和性至关重要**：在双实例集群中，会话感知路由的缓存命中率（96.3%）比轮询/最少负载路由（92.7%）高 3.6 个百分点，p95 JCT 降低 1.2–5.1 秒。
- **策略选择在高前缀重用率时更重要**：当跨轮前缀重用率 η ≥ 0.5 时，不同策略的 JCT 差距扩大（如 η=0.9 时 InferCept 比 Autellix 快 3.3 倍）；η 低时差距淹没在校准误差内。
- **智能体感知策略在工具延迟较大时更有效**：当工具延迟放大到≥1 倍基线时，Continuum/InferCept 优于 vLLM-FCFS；双向分布中，静态阈值（2 秒）已足够，受限于 SWE-Bench 工具延迟的双峰特性。
- **前缀缓存是主导优化**：消融实验表明，开启前缀缓存对 JCT 的改进远远大于调度策略本身（scenario: 缓存关闭时 p95 延迟升高 2.13 倍）。
- **CXL 带宽是次级杠杆**：提高 CXL 有效带宽在中高负载（JPS=0.08–0.10）下额外提升性能（≥9.8%），但在极高负载下饱和，仅改善尾部延迟。

## 7. 优点：方法或实验设计上的亮点

- **创新模拟架构**：以程序为粒度，保留轮次依赖、工具间隙、缓存局部性和多层次 KV 管理，补足现有模拟器（如 Vidur、APEX）空白。
- **模块化设计**：五个模块（编排器、工具模拟器、路由器、调度器、KV 驻留模型）各自独立且可插拔，易于扩展新的策略。
- **忠实度高**：在 80 个单元上误差 < 6%，且保留策略相对排序，可用于可靠的设计空间探索。
- **低成本探索**：可在普通 CPU 上运行，无需 GPU 小时，使得大规模配置扫描可行。
- **详细消融与分解**：通过前缀缓存消融、工具延迟扫描、CXL 带宽扫描等，清晰分离各因素贡献（如调度 vs. 缓存）。
- **公开化设计空间分析**：提供了多组实验（会话亲和性、前缀重用率、工具延迟、KV 层次）的详细结果，具有启发性。

## 8. 不足与局限

- **模型和硬件覆盖有限**：仅验证了 Llama-3.1-8B 和 70B 两个尺寸，以及三款 NVIDIA GPU；未涵盖 TPU、AMD GPU、MoE 模型（如 Mixtral）等常见部署选项。
- **工作负载局限**：仅使用 SWE-Bench Verified 单个数据集，工具时长分布为双峰型，可能不完全代表一般 agent 场景（如调用外部 API 的长尾分布）。模拟器需要更多工作负载以验证泛化性。
- **agent 侧非确定性未建模**：回放模式假定每次运行工具调用相同，未考虑同一 agent 在不同运行中可能产生不同行为（生成模式提供了预测能力但不作为验证焦点）。
- **继承假设**：继承了 LLMServingSim 2.0 的解析网络和基于 profile 的操作符假设，可能忽略某些细粒度硬件交互。
- **校准偏差**：不同硬件平台上存在一致的校准偏差（如 H100 稍低估，RTX 3090 稍高估），但均在 6% 内。可能存在未报告的潜在偏差。
- **仿真速度**：论文声称在 CPU 上运行但未提供具体运行时间对比；与真实系统比肯定更慢，但仍需量化。
- **实验局限性**：速度保留验证中所有策略的加速比差异很小（<3%），因此保留排序的测试区分度有限。论文承认这一点。
