## 摘要
医疗智能体系统日益被期望支持交互式临床决策，而不仅仅是静态问答。在这种场景下，有效的智能体必须能跨演化病例复用过往经验，然而现有记忆机制往往保留原始历史轨迹，这些轨迹冗余、有噪声且难以管理。更重要的是，它们很少区分哪些记忆对未来推理真正有用。这限制了它们积累紧凑可靠经验以进行长期临床推理的能力。为弥补这一差距，我们提出SkeMex，一种部署后自进化框架，通过基于技能的记忆提升医疗智能体，而无需更新模型权重。SkeMex将信息丰富的交互轨迹提炼为编码可复用程序性知识的结构化技能，并将其组织成涵盖通用、任务特定和动作级经验的多分支仓库。为确定哪些记忆应被复用和保留，SkeMex从环境反馈中估计上下文相关的效用，并以此指导价值感知的检索与仓库治理。闭环的“读-写-评估-治理”生命周期通过写入新技能、更新效用、促进有用记忆和移除有害条目来支持持续进化。跨多样临床任务的实验表明，SkeMex在离线和在线设置中均持续优于代表性的基于记忆的智能体。它还能跨模型主干泛化，并支持可迁移的技能记忆。所有数据和代码将公开发布。

## Abstract
Medical agent systems are increasingly expected to support interactive clinical decision making rather than only static question answering. In such settings, effective agents must reuse prior experience across evolving cases, yet existing memory mechanisms often retain raw historical traces that are redundant, noisy, and difficult to govern. More importantly, they rarely distinguish which memories are truly useful for future reasoning. This limits their ability to accumulate compact and reliable experience for long-horizon clinical reasoning. To close this gap, we propose SkeMex, a post-deployment self-evolution framework that improves medical agents through a skill-based memory without updating model weights. SkeMex distills informative interaction trajectories into structured skills that encode reusable procedural knowledge, and organizes them into a multi-branch repository spanning general, task-specific, and action-level experience. To determine which memories should be reused and retained, SkeMex estimates context-dependent utility from environment feedback and uses it to guide value-aware retrieval and repository governance. A closed-loop ``Read--Write--Assess--Govern" lifecycle further supports continual evolution by writing new skills, updating utilities, promoting useful memories, and removing harmful entries. Experiments across diverse clinical tasks show that SkeMex consistently outperforms representative memory-based agents in both offline and online settings. It also generalizes across model backbones and supports transferable skill memory. All data and code will be released publicly.

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出 **SkeMex** 框架，一种部署后自进化（post-deployment self-evolution）方案。其核心是通过一个不断进化的**外部技能记忆库（skill memory）** 来增强智能体，而**不需要更新主干的LLM模型权重**。这类似于一个非参数的强化学习过程，将交互经验蒸馏为可复用的结构化技能。

- **关键技术细节**：
    1.  **记忆制定（Memory Formulation）**：
        - 将交互轨迹转化为“技能”，这是一种比原始轨迹更紧凑、更可迁移的程序性知识单元。
        - 技能存储在一个三分支（multi-branch）仓库中：
            - `M_gen` (通用分支): 可迁移的推理策略和通用临床原则。
            - `M_task` (任务级分支): 特定任务族或临床类别相关的模式。
            - `M_act` (动作级分支): 工具使用的操作知识（如参数格式）。这种分层结构避免了不同抽象级别技能的互相干扰。

    2.  **价值感知检索（Value-Aware Retrieval）**：
        - 在每次任务开始时执行一次检索，为整个轨迹提供稳定的技能上下文。
        - 检索评分结合了**语义相似度**、**历史效用**（U(m|κ) 使用类别条件化估计）和**记忆强度**（结合艾宾浩斯遗忘曲线的时间衰减）。
        - 采用了分支感知的Top-K选择，确保各分支都能贡献经验。

    3.  **轨迹到技能的蒸馏（Trajectory-to-Skill Distillation）**：
        - 通过一个**门控轨迹缓冲区**，过滤掉基础设施错误、机械重复和微不足道的成功案例，只保留信息丰富的轨迹。
        - 使用**两遍蒸馏**流程：分析遍提取可复用模式，变异遍将模式转化为新技能草案或对现有技能进行修补（PATCH）。
        - 新技能必须通过**新颖性**和**质量**门控审核，确保其独特性和可操作性。

    4.  **效用驱动的技能估值（Utility-driven Skill Valuation）**：
        - 在窗口级别聚合多条轨迹的反馈，使用 **优势函数（Advantage, A_τ）** 评估技能效用，而非绝对奖励。优势值 = 轨迹奖励 - 该类别基线的指数移动平均。
        - 根据技能是否被积极采纳、有害采纳或忽略，分配正/负信用并更新其效用值（u_i），促进良性经验的正向循环。

    5.  **闭环自进化（Closed-loop Self-evolution）**：
        - 整个框架遵循 **"读-写-评估-治理"**（Read-Write-Assess-Govern）的闭环生命周期。
        - `Govern` 操作定期运行，负责合并冗余技能、弃用低效用技能、将持续有效的技能升级为“成熟”状态，并维护仓库容量，确保其紧凑和可靠。

- **公式/算法流程**：
    - **形式化**：问题建模为记忆马尔可夫决策过程（M-MDP）。
    - **整体更新**：`M(w+1) = G(V(W(M(w), B(w))))`，其中 `B(w)` 为门控缓冲轨迹，`W` 为写入算子，`V` 为估值算子，`G` 为治理算子。

    > 整个算法流程如Algorithm 1所示，是一个清晰的任务流：智能体在新的任务开始时，首先`Read`（读取并检索相关技能），然后在`步骤7-18`中执行任务（`Act`），期间技能作为上下文指导其行为。执行完毕后，轨迹经过`步骤20-22`的筛选进入窗口缓冲区。当缓冲区满时，执行`Write`（蒸馏技能）和`Assess`（评估效用），最后定期执行`Govern`（治理仓库）。

1.  **显著超越现有方法**：SkeMex在离线和在线设置中，均**持续、大幅地优于** ReAct 和所有16种代表性的记忆型智能体基线。例如，在离线域内任务上，SkeMex 将 DeepSeek-V3.2 的平均分从 ReAct 的 48.20% 提升至 56.08%，提升了 7.88 个百分点。
2.  **跨领域和跨模型泛化能力强**：SkeMex 的技能库不仅在域内任务上表现优异，在**未见过的域外基准（OOD）** 上也展现出强大的泛化能力。此外，用 DeepSeek-V3.2 构建的技能库可以无缝迁移到 Qwen3.6-Plus、Claude Sonnet-4.6 等其他模型上，同样带来显著提升，证明了技能的可转移性。
3.  **每个组件都至关重要**：消融实验表明，**缓冲区管理**、**技能蒸馏**、**多分支结构**、**价值感知检索**和**闭环治理**等所有模块都对最终性能有显著贡献，移除任何一个都会导致性能下降。特别是，去除了效用驱动的估值后，性能下降最为明显。
4.  **稳定性与鲁棒性**：敏感性分析显示，SkeMex 的核心超参数在合理范围内都能保持稳定的良好性能，证明了框架的鲁棒性。

### 7. 优点

- **创新性**：提出了一种新颖的“从经验中学习”范式，将复杂的交互经验蒸馏为结构化、可迁移的技能，并通过一个受强化学习启发的非参数效用函数来指导记忆的演化，无需更新模型参数，这在医疗领域尤为重要。
- **方法论完备性**：“读-写-评估-治理”闭环生命周期设计精巧，涵盖了经验获取、提炼、评估和精炼的完整过程，形成了一个自我强化的良性循环。
- **实验的严谨与全面性**：实验设计极为详尽，基准对比、消融、敏感性、跨模型和跨场景测试一应俱全，为结论提供了强有力的支撑。这种研究范式是值得学习的典范。
- **实用性与可拓展性**：SkeMex 被设计为一个即插即用（plug-and-play）的框架，可以与任何主干模型配合使用。它无需昂贵的模型重训，也不需要大量算力（控制器端CPU即可运行），这极大地降低了其在真实世界医疗应用中的部署门槛。

### 8. 不足与局限

- **实验环境的局限性**：评估数据集（即使是交互式的）也无法完全模拟真实临床环境的复杂性，如繁复的病史、多变的机构工作流和多元的决策约束。结果可能无法完美外推到真实世界。
- **推理开销增加**：SkeMex 带来了可观的推理延迟和计算成本（约为ReAct的两倍）。这是为了获得更可靠、更结构化的推理所付出的代价，在实时性要求极高的场景下可能是一个问题。
- **主干模型覆盖不全**：虽然测试了多个主流模型（DeepSeek, Qwen, Claude, Kimi, GLM），但未穷尽所有可用的基础模型。建议未来可以在更多模型上进行验证。
- **失败模式**：论文指出了典型的失败案例：工具调用的基础性错误（如参数格式错误）会消耗大量的预算，导致智能体草率下结论，未能进行充分的检查，从而产生不精确的诊断。这说明框架对智能体底层的工具使用能力仍有依赖。
- **潜在风险**：如果技能库学到了错误的或有害的模式，可能会被无差别地复用，造成系统性错误。虽然治理机制能缓解，但在完全信任的自主医疗代理部署前，仍需要**充分的人工监督**。
