## 摘要
大型语言模型在代理记忆流水线中的位置——介于检索已存储事实（广泛基准测试）的回忆平面与通过替换、释放、清除（基本未经测试）对其进行变异的控制平面之间——决定了系统能恢复哪些遗忘失败模式。在385个案例的对抗性表面上比较了十三种系统配置，我们观察到三种具有部分互补覆盖范围的放置模式：确定性原语足以处理词汇/时间类别，但无法规范化（标识符混淆上为5%，跨语言上为0%）；写入时的大型语言模型可恢复规范化（100%），但无法帮助意图感知删除（前缀冲突和复合事实上的0%）；突变时钩子可恢复意图感知删除（78-85%），并同时照亮几乎所有类别（总体91.7-93.2%，每次385案例运行0.17美元，突变延迟2.3秒/案例 vs 确定性64-191毫秒/案例，回忆路径不变）。我们通过ForgetEval揭示了权衡，这是一个1000案例模板套件加上385案例对抗层（132个手工制作+253个大型语言模型起草并由预言机验证），通过确定性子字符串匹配评分，并配以六方法适配器协议（诚实不适用评分），可在130行中引入异构记忆存储。一致性由10名标注者的IAA（Fleiss' kappa = 0.958）和77个外部作者子集（四位匿名贡献者）验证，该子集复制了规范化不对称性并放大了联合放置的提升（+27.8个百分点）。生产失败主要是遗忘失败而非回忆失败，但现有基准仅测量回忆。ForgetEval和所有适配器均在MIT许可下发布。

## Abstract
Where an LLM sits in an agent memory pipeline -- between the recall plane that retrieves stored facts (extensively benchmarked) and the control plane that mutates them via supersede, release, purge (largely untested) -- shapes which forgetting failure modes the system recovers. Comparing thirteen system configurations on a 385-case adversarial surface, we observe three placement regimes with partly complementary coverage: deterministic primitives suffice for lexical/temporal categories but fail canonicalization (5% on identifier-obfuscation, 0% on cross-lingual); inscribe-time LLM recovers canonicalization (100%) but cannot help intent-aware deletion (0% on prefix-collision and compound-fact); a mutation-time hook recovers intent-aware deletion (78-85%) and brightens nearly all categories simultaneously (91.7-93.2% overall, $0.17 per 385-case run, 2.3s/case mutation latency vs. 64-191ms/case deterministic, recall path unchanged).   We expose the trade-off via ForgetEval, a 1000-case templated suite plus a 385-case adversarial layer (132 hand-crafted + 253 LLM-drafted oracle-validated) scored by deterministic substring match, paired with a six-method Adapter Protocol with honest N/A scoring that lets heterogeneous memory stores enter in 130 lines. Admission is corroborated by 10-annotator IAA (Fleiss' kappa = 0.958) and a 77-case external-authored subset (four blind contributors) that replicates the canonicalization asymmetry and amplifies the joint-placement lift (+27.8 pt). Production failures are predominantly forgetting failures rather than recall failures, yet existing benchmarks measure only recall. ForgetEval and all adapters are released under MIT.

# 论文总结：Control-Plane Placement Shapes Forgetting

## 1. 核心问题与整体含义（研究动机和背景）
- **生产中的遗忘失败比回忆失败更严重**：现有LLM代理记忆系统（如MemGPT、MEM0等）和基准（LongMemEval、MTEB、BEIR）几乎只关注“召回”能力——检索到正确的事实。但实际生产事故往往是“遗忘”失败：旋转移交的凭证仍被推荐、GDPR删除的记录依然浮现、用户矛盾的职位信息同时出现。这些是控制平面（执行supersede/release/purge等变异原语）的问题，而非回忆平面的问题。
- **控制平面放置位置决定遗忘模式**：LLM可以在记忆流水线的不同位置介入——写入时（inscribe-time）、变异时（mutation-time）、或者完全不介入（确定性原语）。论文系统研究了这种架构放置对十种对抗性攻击类别遗忘性能的影响，发现不同放置机制具有部分互补的覆盖范围，而生产系统需要联合放置才能全面恢复。

## 2. 方法论：核心思想、关键技术细节
### 2.1 ForgetEval评估套件
- **结构**：包含两部分
  - **模板套件（1000个案例）**：5个遗忘家族（supersession、decay、amnesia、purge、drift），每个家族有4个子模板，生成确定性案例。
  - **对抗层（385个案例）**：132个手工核心 + 253个LLM起草、预言机验证，涵盖10个攻击类别：substring_trap、prefix_collision、paraphrase_supersession、negation_trap、temporal_qualifier、shared_attribute、compound_fact、identifier_obfuscation、cross_lingual_identifier、recursive_supersession。
- **评分方式**：确定性子串匹配（top-10召回中must_contain必须存在、must_not_contain必须不存在），无需LLM评判器，保证可复现。

### 2.2 Adapter协议
- **6个方法**：3个强制回忆平面原语（reset、inscribe、recall_texts）和3个可选控制平面变异（supersede、release、purge），未实现时返回N/A。
- **行为契约**：任何支持add/delete组合的系统都可以通过130行Python适配器接入，使异构存储（确定性向量库、LLM写入、知识图谱等）在相同协议下公平比较。

### 2.3 三种LLM放置机制
- **确定性原语**（纯向量/BM25）：无LLM介入，依赖精确匹配和嵌入相似度。
- **写入时LLM**（inscribe-time LLM）：在写入时用LLM提取标签、实体链接，供阅读时使用（如A-MEM、MEM0+v3、Letta标签侧）。
- **变异时钩子**（mutation-time hook）：在supersede/release/purge时调用LLM进行计划（如LETHE+LLM、LangGraph+LLM），使用窄JSON提示。召回路径无LLM，保持低延迟。

## 6. 主要结论与发现
1. **三种放置机制互补，不替代**：
   - 确定性原语：词汇/时间类别通过率>95%，但不能规范化标识符（identifier_obfuscation仅5%，cross_lingual_identifier 0%）。
   - 写入时LLM：可恢复规范化（100%），但无法处理前缀冲突（0%）和复合事实编辑（0%）。
   - 变异时钩子：恢复意图感知删除（78-85%），同时提升几乎所有类别（整体91.7-93.2%）。
2. **变异时钩子与后端无关**：在LETHE和LangGraph上产生几乎相同的提升（±2pt），且跨LLM型号一致（DeepSeek-V3升幅28-30pt，Qwen-2.5-72B升幅13pt）。
3. **联合放置（inscribe+mutation）必要但不充分**：Letta+LLM比单独Letta提升+20.9pt，但因缺少部分编辑原语，无法达到LETHE+LLM水平。
4. **现有基准测量不同维度**：MemPalace在ForgetEval上0/385（遗忘失败），但在Memora上40%（回忆成功），表明Recall和Forgetting是正交轴。
5. **复合事实是原语存在测试**：只有具有部分编辑原语的系统才能通过，不应视为遗忘能力差异。

## 7. 优点
- **提出遗忘的新维度**：首次系统研究控制平面放置对遗忘的影响，而非仅关注召回。
- **Adapter协议+诚实N/A评分**：使异构记忆系统可以在统一接口下公平比较，降低社区参与门槛（130行Python）。
- **确定性子串评分**：无需LLM评判器，保证评估可复现，避免LLM自我评估的偏见。
- **多层次验证**：手工核心+LLM起草+独立外部作者子集+多标注者IAA+跨LLM家族评判器一致性检查，证明结果并非偶然。
- **资源消耗透明**：公开每次运行成本（$0.17/385 cases）和延迟，便于实际部署决策。
- **开源**：所有代码、数据、适配器在MIT许可下发布，鼓励社区贡献。

## 8. 不足与局限
- **语言覆盖不均**：对抗层为英语，cross_lingual_identifier类别仅覆盖9个语系，Non-Latin样薄（如Devanagari仅1例、Thai 1例、Arabic 2例），无法统计区分LLM钩子系统间的差异。
- **记忆系统覆盖有限**：缺失多个商业系统（Redis、AutoGen Memory、Zep CE因已弃用未测），且部分系统因API不兼容（Cognee）或docker基础设施限制（Graphiti、Letta）仅评估了有限功能。
- **LLM钩子质量敏感**：提升幅度高度依赖LLM的JSON跟随能力（Llama-3.1-70B无法解析提示，退化为确定性基线），不同供应商模型成本差异大（Qwen比DS-V3贵56%但提升更小）。
- **部分类别依赖LLM起草**：253/385案例由DeepSeek-V3起草，虽然经预言机验证和外部作者子集支持，但仍不能完全排除与LLM钩子的归纳偏差重叠风险（论文通过手工子集分析、跨家族评判器审计和外部作者子集部分缓解）。
- **复合事实类别定义歧义**：人与LLM评判器在“部分编辑”语义上存在分歧，导致10/21的人机不一致。
- **缺乏生产环境生态效度**：论文提供了结构映射至已知生产事故，但未进行实际生产轨迹关联实验，遗忘能力与真实泄漏的相关性尚待证明。
