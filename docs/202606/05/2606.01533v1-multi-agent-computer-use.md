## 摘要
当前的计算机使用智能体（CUA）主要作为单一串行智能体部署。这种设置对于需要任务分解、并行执行以及基于新信息持续重新规划的复杂长周期任务而言并非最优。本文主张应转向评估和构建多智能体计算机使用（MACU）系统。这些系统强调规划和并行执行，缓解了单智能体CUA的诸多缺陷。我们提出了一种通用的多智能体设置，其中管理模型将计算机使用任务分解为有向无环图（DAG），编码子智能体的相关依赖和目标。在每次迭代中，管理者派遣并行的CUA子智能体执行DAG就绪前沿上的节点，并根据子智能体传来的新发现持续修订DAG（添加、取消或重写节点）。这种设计将计算机使用的部分可观察环境作为首要挑战处理：下游智能体可能无法重新观察到的信息通过管理者和DAG结构得以保留并向前传递。我们在桌面（OSWorld）和网页导航（Online-Mind2Web、WebTailBench、Odysseys）基准上证明，MACU相较于强单智能体基线持续提升3.4–25.5%，展现出更有利的测试时缩放，并能解决单智能体CUA陷入停滞的复杂长周期任务。在长周期网页导航基准Odysseys上，MACU将平均任务完成挂钟时间提升了约1.5倍，证明了其在加速传统缓慢CUA流水线方面的有效性。我们的发现强调，多智能体协调是扩展计算机使用智能体以实现更长时间高效工作的有前景方向。我们在https://jykoh.com/multi-agent-computer-use 发布了所有代码和交互式可视化。

## Abstract
Computer use agents (CUAs) today are primarily deployed as single serial agents. This setup is suboptimal for complex long-horizon tasks that benefit from task decomposition, parallel execution, and consistent re-planning based on new information. In this paper, we argue that we should instead move towards evaluating and building multi-agent computer use (MACU) systems. These systems, which emphasize planning and parallel execution, alleviate many of the shortcomings of single-agent CUAs. We propose a general multi-agent setup in which a manager model decomposes computer use tasks as a directed acyclic graph (DAG), encoding relevant dependencies and goals for subagents. At each iteration, the manager dispatches parallel CUA subagents to carry out nodes on the ready frontier of the DAG, and continuously revises the DAG (adding, canceling, or rewriting nodes) as new findings arrive from subagents. This design treats the partially observable environment of computer use as a first class challenge: information that downstream agents may not be able to re-observe are retained and passed forward through the manager and DAG structure. We demonstrate that MACU consistently improves over strong single-agent baselines by $3.4-25.5\%$ on desktop (OSWorld) and web navigation (Online-Mind2Web, WebTailBench, Odysseys) benchmarks, exhibits more favorable test-time scaling, and solves complex long-horizon tasks where single-agent CUAs get stuck. On Odysseys, a long-horizon web navigation benchmark, MACU improves average task completion wall-clock time by ${\sim} 1.5 \times$, demonstrating its efficacy in speeding up traditionally slow CUA pipelines. Our findings highlight that multi-agent coordination is a promising axis for scaling computer use agents to work productively for longer and more effectively. We release all code and interactive visualizations at https://jykoh.com/multi-agent-computer-use.

## 1. 核心问题与整体含义
- **研究动机**：当前计算机使用代理（CUA）主要作为单串行智能体部署，处理复杂、长时任务时存在次优性，包括难以进行任务分解、并行执行以及基于新信息的持续重新规划。部分可观察环境（如桌面OS、动态网页）使得单智能体容易陷入局部错误或无法回溯。
- **整体含义**：本文倡导转向多智能体计算机使用（MACU）系统，通过规划与并行执行提升CUA处理复杂长时任务的能力，并为测试时计算缩放提供新维度。作者认为多智能体协调是扩展CUA高效工作的重要方向。

## 2. 方法论：核心思想与关键技术
- **核心思想**：使用一个**管理者代理**（Manager）将用户任务分解为**有向无环图（DAG）**的子任务节点，并行调度多个同构的CUA子代理执行就绪节点，并根据子代理反馈持续修订DAG（添加、取消、重写节点）。
- **关键技术细节**：
  - **管理者（Manager）**：实现为LLM调用，负责：
    1. 初始DAG分解：基于任务指令和初始VM截图生成DAG（JSON格式）。
    2. 重规划：子代理完成后，管理者基于当前DAG、子代理的截图和响应、父节点上下文，决定对DAG的编辑（添加/删除/修改节点或指令、取消运行中的节点），受限于重规划预算B。
    3. 文件管理：通过文件系统差异识别需保存的文件，并在子任务间传递。
    4. 后续跟进：子代理完成后管理者可让其继续工作或总结终止。
    5. 最终聚合：所有子任务完成后，管理者汇总结果。
  - **子代理（Subagents）**：每个子代理运行标准ReAct循环，在独立VM中执行，接收来自管理者的指令。所有子代理基于相同的CUA骨干模型，无专门化。
  - **算法流程**（Algorithm 1）：
    1. 管理者分解任务生成初始DAG。
    2. 循环直到DAG无未完成节点：
       - 找出就绪节点（依赖全部完成且未运行）。
       - 并行启动最多N个子代理执行就绪节点。
       - 等待任一子代理完成或检查点。
       - 对完成的节点：收集结果、文件管理、若预算未用完则执行重规划。
       - 若有空闲槽位，可进行额外重规划（如利用空闲容量）。
       - 若到达最终聚合节点，则汇总输出。
  - **部分可观察性处理**：通过DAG结构和管理者传递关键状态（截图、文件diff、父节点结果），确保下游子代理能获得必要上下文。

## 6. 主要结论与发现
- MACU在四个基准上比单智能体持续提升成功率：OSWorld +4.7%，Online-Mind2Web +3.4%，WebTailBench +8.7%，Odysseys +25.5%。
- 在长时任务（Odysseys）上挂钟时间中位数降低约1.5倍（从162分钟到110分钟），并行加速明显。
- 测试时计算缩放更有利：随动作数增加，MACU成功率持续上升而单智能体很快饱和。
- 重规划预算B至关重要：B=0 vs B=10时成功率从25.0%提升至58.3%（OSWorld子集）。
- 管理者模型越强，MACU增益越大（Opus 4.6 vs 弱模型）。
- MACU特别适合可并行分解的任务（如信息收集、对比、重试），而对本质上串行的任务（部分Online-Mind2Web）增益较小且可能增加时延。
- 大多数任务在运行过程中DAG会增长，表明管理者自适应调整。

## 7. 优点
- **方法简洁通用**：仅需两种代理（管理者和同构子代理），不依赖专门化模型，可直接利用未来更强的CUA型号。
- **显式处理部分可观察性**：通过DAG结构、管理者传递状态、文件存档等机制，保留和传递关键上下文，不像多数多智能体LLM系统假设全可观察。
- **有效并行与重规划**：DAG分解 + 动态修订使任务能并行执行并从中错误恢复，避免单智能体卡死。
- **全面的实验与消融**：覆盖多种基准、多种模型规模、规划预算、并行度、管理者能力，结果具有强说服力。
- **公开代码与可视化**：促进可重复性和后续研究。

## 8. 不足与局限
- **推理成本增加**：并行子代理和管理者调用增加计算成本，部分任务（如Online-Mind2Web）挂钟时间反而增加，需根据任务特点调整并行度和预算。
- **仅针对可分解任务有效**：对于串行性强的任务（如单步GUI操作），MACU收益有限，甚至可能引入开销。未讨论如何自动判断是否使用多智能体。
- **系统复杂性**：需要管理隔离VM、文件diff、状态传递等基础设施，增加部署和维护难度。
- **评估未涵盖真实风险**：基准任务在受控环境中进行，未涉及真实用户数据、隐私、安全性等。论文虽在Broader Impacts中讨论了潜在风险，但实验未验证安全机制。
- **模型依赖性**：当前结论基于特定骨干（Qwen3.6-27B）和有限管理者模型，宏观适用性需更多跨模型验证。
- **资源信息不完全**：未提供每个消融实验的详细训练/推理总时长、显存占用等，不利于精确成本评估。
- **未进行端到端多智能体强化学习或微调**：作者假设进一步训练可提升性能，但未实验验证。
