## 摘要
长时间运行的AI智能体需要持久化记忆。记忆支持跨会话的学习，减少重复的上下文注入，并能够审计过去的决策。当前的智能体记忆系统和数据库范式将记忆视为存储。它们将正确性定位于记录、嵌入或边。每种范式仅提供长期记忆所需的部分能力。结果导致了四种反复出现的故障模式：无限制的增长、缺失语义修正、容量驱动的遗忘以及只读检索。在我们的愿景中，长期智能体记忆是一种新的数据管理工作负载。其正确性是状态轨迹的属性，而非单个记录的属性。我们将其形式化为受控演化记忆（GEM）。GEM用四个状态级操作符替代记录级数据库操作：摄入、修正、遗忘和检索。六个正确性条件控制状态如何演化。三个结构性观察表明，无论采用何种存储模型，没有任何记录级系统能够满足这些条件。我们在属性图后端上实现了该抽象的原型MemState。MemState验证了可行性，并揭示了与原生引擎之间的差距。我们概述了三个研究方向，将面向记忆的数据管理定义为一个工作负载。

## Abstract
Long-running AI agents need persistent memory. Memory supports learning across sessions, reduces repeated context injection, and enables auditing of past decisions. Current agent memory systems and database paradigms treat memory as storage. They localize correctness at records, embeddings, or edges. Each supplies only some of the capabilities that long-term memory requires. The result is four recurring failure modes: unregulated growth, missing semantic revision, capacity-driven forgetting, and read-only retrieval. In our vision, long-term agent memory is a new data-management workload. Its correctness is a property of the state trajectory, not of individual records. We formalize this as Governed Evolving Memory (GEM). GEM replaces record-level database operations with four state-level operators: ingestion, revision, forgetting, and retrieval. Six correctness conditions govern how the state evolves. Three structural observations establish that no record-level system can satisfy these conditions, regardless of the storage model. We realize the abstraction in MemState, a prototype on a property-graph backend. MemState validates feasibility and exposes the gap to a native engine. We outline three research directions that define memory-centric data management as a workload.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：长期运行的AI智能体需要持久记忆来支持跨会话学习、减少重复上下文注入并审计过去决策。然而，当前智能体记忆系统和数据库范式都将记忆视为**存储**，将正确性局限于记录、嵌入或边的层面，导致四个反复出现的故障模式：
  1. 无节制增长（冗余条目积累）
  2. 缺失语义修订（更新事实与过期事实共存）
  3. 容量驱动遗忘（按年龄而非重要性驱逐）
  4. 只读检索（检索不改变记忆状态）
- **背景**：现有系统（如ChatGPT、Claude、Cursor等）继承传统数据库的CRUD操作，但记忆的正确性应是**状态轨迹**的属性，而非单个记录。论文指出长期智能体记忆是一个**新的数据管理工作负载**，需要全新的数据基础。

## 2. 方法论：核心思想、关键技术细节

### 核心思想：受控演进记忆（Governed Evolving Memory, GEM）

- GEM将记忆状态定义为元组 \( M_t = (D_t, S_t, P_t) \)：
  - \( D_t \)：存储内容，组织为**语义单元**（每个单元持有所有相关数据元素及其值历史和显著性信号）
  - \( S_t \)：结构组织（语义单元之间的连接，如扩展边和关联边）
  - \( P_t \)：演进策略（声明式规则，指定何种操作在何种条件下可执行）
- 用四个**状态级运算符**替代记录级CRUD：
  - **摄入（Ingestion）**：将新输入整合进现有语义单元，保留历史值
  - **修正（Revision）**：根据内部证据合并、传播更新，沿依赖边（扩展边）传播，保留废弃值的来源
  - **遗忘（Forgetting）**：按显著性（访问频率）分级衰减（压缩→隐藏→归档），而非按容量或时间二元删除
  - **检索（Retrieval）**：返回输出并**同时更新状态**（增加访问单元的显著性），使检索成为写操作

### 六个正确性条件（C1–C6）

- **C1 查询声音性**：返回最新非归档值作为当前值
- **C2 转换声音性**：每次状态转换必须遵守策略 \( P_t \)，不返回废弃值作为当前值
- **C3 依赖一致性**：沿有传播语义的扩展边，更新一个单元触发评估相连单元
- **C4 来源保存**：遗忘和修正保留可达单元的证据链
- **C5 有界活跃状态**：活跃记忆大小受策略定义的边界 \( \beta(n) \) 限制，归档内容可恢复
- **C6 检索诱导适应**：每次访问更新显著性，重复检索降低衰减资格

### 三个结构性观察

- **观察1**：纯函数检索无法满足C6（因为C6要求检索本身引发状态转换）
- **观察2**：在CRUD引擎上无法同时满足C5（相关性驱动的遗忘）和C6（除非检索是写操作）
- **观察3a/3b**：无语义单元的追加存储无法满足C2；无类型传播无法满足C3

这些观察证明：没有任何记录级系统（无论存储模型）能满足GEM的条件。

### 原型MemState

- **实现**：在嵌入式属性图引擎Kuzu上实现GEM，以**话题（topic）**为语义单元，每个话题包含摘要、嵌入、字段及值历史，并通过两种边（扩展边/关联边）连接。
- **策略**：采用声明式规则（如“当字段变化时，标记依赖话题进行修正”），在提交事务前检查策略，违反则中止，从而将C2提升为数据模型级保证。
- **异步操作**：遗忘和修正作为策略触发的后台维护运行。

## 6. 主要结论与发现

- 长期智能体记忆不应被视为数据库问题，而应被视为**新的数据管理工作负载**，其正确性在状态轨迹层面。
- GEM框架通过四个状态级运算符和六个正确性条件，提供了解决四种故障模式的理论方案。
- 任何基于CRUD的记录级系统都**无法**满足GEM的条件，必须构建原生引擎。
- MemState原型验证了GEM在现有属性图引擎上的可行性，但也暴露了与原生引擎之间的差距（如字段历史、传播边、策略编译等方面的性能优化无法直接表达）。
