## 摘要
长期LLM智能体需要持久记忆，能够跟踪变化的事实并在不同会话中提供相关证据。现有的记忆系统通常将观测结果存储为孤立记录、摘要或索引片段，这使得证据聚合、事实修订和记忆维护变得困难。我们提出Infini记忆，一种可维护的基于文本的持久记忆架构，将智能体记忆视为主题结构化的文档。每个主题文档作为一个语义单元，用于收集相关证据、保留元数据并随时间修订事实。新的观测结果首先暂存在缓冲区中，并定期整合为连贯的文本上下文。在推理时，一种智能体检索过程让LLM通过迭代工具调用（而非单次检索步骤）读取记忆。在MemoryAgentBench上，Infini记忆取得了64.7%的整体得分。消融实验表明，主题结构化维护和迭代证据检查改善了长期记忆使用的互补方面。

## Abstract
Long-term LLM agents need persistent memory that can track changing facts and provide relevant evidence across sessions. Existing memory systems often store observations as isolated records, summaries, or indexed fragments, which makes evidence aggregation, fact revision, and memory maintenance difficult. We propose Infini Memory, a maintainable text-based persistent memory architecture that treats agent memory as topic-structured documents. Each topic document serves as a semantic unit for collecting related evidence, preserving metadata, and revising facts over time. New observations are first staged in a buffer and periodically consolidated into coherent textual contexts. At inference time, an agentic retrieval procedure lets the LLM read memory through iterative tool calls rather than a single retrieval step. On MemoryAgentBench, Infini Memory achieves 64.7% overall score. Ablations show that topic-structured maintenance and iterative evidence inspection improve complementary aspects of long-term memory use.

### 1. 核心问题与整体含义

- **研究动机**：长期 LLM 智能体需要持久记忆来跨会话跟踪动态事实、提供相关证据。现有记忆系统（如 MemGPT、MemoryBank、HippoRAG-v2 等）将观测存储为孤立记录、摘要或索引片段，面临四个关键缺陷：记忆碎片化（同一用户/事件证据分散）、记忆冲突（新旧事实并存未调和）、压缩损失（总结后丢失时间与来源信息）、检索不足（单次返回片段，难以支持多步推理）。
- **整体含义**：本文提出将持久记忆视为一个生命周期维护问题，而非单纯的存储与检索。记忆模块应当支持：高质量写入（抽取持久信息）、主动维护（分组、调和、保留元数据）以及多步读取（展开上下文、聚合证据）。

### 2. 方法论

- **核心思想**：用**主题文档**（topic documents）作为记忆的基础单元。每个文档按主题组织相关证据，携带元数据（seq, time, source），支持动态分裂、合并与重写。写入通过缓冲区（CURRENT）暂存，达到阈值后触发改写与合并；读取时 LLM 可通过迭代工具调用（agentic retrieval）主动搜索和扩展证据。
- **关键技术细节**：
  - **文档表示**：每个文档包含 YAML 头（id, summary, token_count, 时间戳, 更新日志）和主体（按 heading 分组，条目带 `<seq=…,time=…,source=…>` 签名）。
  - **写入管道**：新内容先append到 CURRENT 缓冲区；当 token 数 ≥ τ_tok 或时间差 ≥ τ_time 时触发 flush（公式(1)）。之后将 CURRENT 重写为 REWRITE_CURRENT（去重、调和矛盾），再通过计划（Plan）决定是更新已有主题文档还是创建新文档（Algorithm 1, 2）。定期执行分裂（超过 5000 token 的文档）与合并（低于 1000 token 且主题相似的文档）。
  - **检索策略**：
    - **混合变体（Infini Memory-H）**：LLM 选择候选文档 + BM25 分区检索。
    - **智能体变体（Infini Memory-A）**：LLM 最多 7 轮调用工具（grep, grep_doc, search, list_docs, read_lines），逐步扩大上下文；若证据不足则回退 BM25（Algorithm 3）。
- **设计取舍**：弃用纯向量库（碎片化）、纯知识图谱（建模成本高、自然关系少），采用纯文本后端以保持可读、可编辑、可移植。元数据可扩展支持命名空间、实体模式、访问规则等。

### 3. 实验设计

- **数据集/场景**：在 **MemoryAgentBench** 上评估，该 benchmark 覆盖四个能力维度：Accurate Retrieval (AR)、Test-Time Learning (TTL)、Long-Range Understanding (LRU)、Selective Forgetting (SF)。包含子任务：单/多跳文档 QA、LongMemEval (S⋆)、事件 QA、分类、推荐、摘要、侦探推理 QA、事实巩固单/多跳遗忘等。
- **对比方法**：RAPTOR、MemoRAG、HippoRAG-v2、Mem0、MemGPT、LightMem、REMem。所有方法统一使用 gpt-5-mini 作为基础模型，输入分块大小 4096 token。评判使用 gpt-5 作为 LLM-as-Judge，二值判断。
- **消融实验**：三项关键消融：
  1. **结构维护消融**：固定混合读取，去掉分裂/合并，观察 LongMemEval 精度下降 6.7%（76.0→69.3）。
  2. **检索策略消融**：固定维护，对比 summary-only（41.7%）、混合（76.0%）、智能体（79.3%），智能体增益 +3.3%。
  3. **分裂阈值敏感性**：在 1000、3000、5000、7000、9000 token 下测试，低于 5000 时精度较稳定，高于 5000 时下降明显（最多 -6.3%）。

### 6. 主要结论与发现

- **Infini Memory-A 整体得分 64.7%**，超过最强基线 HippoRAG-v2 达 19.2 个百分点，在 AR（81.2%）、TTL（79.0%）、LRU（79.3%）、SF（83.6%）四个维度均领先。
- **结构维护贡献大于检索升级**（固定读取下移除维护损失 6.7% vs 维护固定下从混合升级到智能体仅获益 3.3%），两者互补。
- **多跳选择性遗忘（FC-MH）仍然是结构性瓶颈**：单跳遗忘可由写入时调和解决，但多跳跨文档推理时，由于不同文档在异步时间点更新，无法保证全局一致性。
- **分裂阈值应对称性敏感**：设置过低（≤3000）影响较小，设置过高（≥7000）导致大文档混杂无关主题，精度显著下降。

### 7. 优点

- **文档式可维护性**：主题文档保留了时间、来源等元数据，支持重写、分裂、合并，使记忆可编辑、可审计，避免碎片化。
- **缓冲区与批量整合**：分离高频写入与低频维护，减少在线维护开销，暂存局部连贯性，有助于去重和矛盾调和。
- **智能体检索增强上下文**：LLM 可迭代搜索、展开本地上下文，避免单次检索的信息碎片问题；混合变体在成本与效果间提供了折中。
- **后端轻量**：默认使用纯文本 + 词法索引，不依赖向量库或图数据库，部署简单，可扩展性强（元数据可承载领域特定字段）。

### 8. 不足与局限

- **多跳选择性遗忘能力弱**：跨文档矛盾调和机制缺失，导致复杂遗忘任务表现差（FC-MH 仅 35.0%），这一点 MemoryAgentBench 作者也指出是通用挑战。
- **评估范围有限**：仅在 MemoryAgentBench 一个 benchmark 上验证，缺少对更长会话（数千轮）、更大记忆库、多模态输入等场景的测试。基座模型仅使用 gpt-5-mini，未验证泛化性。
- **计算开销未量化**：智能体检索的 tool 调用次数（最多 7 轮）和 LLM 推理成本未作统计，实践中可能高于单次检索方法；维护阶段的重写也带来离线计算消耗。
- **阈值敏感**：分裂/合并的 token 阈值对性能影响非对称，需要针对场景调优；默认设置基于单一 benchmark，迁移时可能需要调整。
- **缺乏与最新方法的直接对比**：如 A-MEM（2025 NeurIPS）、REMem 虽被对比但未包含其智能体变体或最优配置，且个别基线得分与原文报告有差异。
