## 摘要
LLM智能体越来越多地部署在需要长时间跨交互历史进行持续推理的长期任务上。要实现大规模部署，智能体需要在会话之间持久地存储、检索和更新自身内存。一个丰富的智能体内存系统生态系统已经出现，涵盖了平面检索、LLM中介提取、整合事实存储以及智能体控制流程。然而，它们的系统级行为尚未得到特征描述。我们首次对智能体内存进行了系统特征分析。首先，我们引入了一个系统导向的分类法，将智能体内存系统沿四个轴进行分类。其次，我们构建了一个阶段感知的性能分析工具，将成本归因于构建、检索和生成。第三，我们在两个基准套件上对十个代表性系统进行了特征描述，揭示了设计选择如何在写入和读取路径上转移成本。最后，我们得出了10条系统建议，涵盖构建调度、能力基线、通过查询量进行摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

## 2. 方法论
### 核心思想
- 提出**四轴分类法**（construction, storage, retrieval, mutability），将智能体内存系统分为四大范式：长期上下文记忆（Long-context）、平面 RAG 记忆（Flat RAG）、结构增强 RAG 记忆（Structure-augmented RAG，进一步分为仅追加型与整合型）、智能体控制流（Agentic control flow）。
- 构建**阶段感知分析工具**（phase-aware profiling harness），将总成本归因于三个逻辑阶段：内存构建（construction）、检索（retrieval）、生成（generation），并记录 API 遥测（token 数量、模型调用次数、延迟）和硬件遥测（GPU 利用率、功耗、HBM 带宽、SM/张量核心活动）。

### 关键技术细节
- **四轴分类**：
  - **Construction**：无/确定型/LLM 中介/智能体控制。
  - **Storage**：原始缓冲区/倒排索引/稠密向量/图/混合存储。
  - **Retrieval**：单次稀疏/稠密搜索/多阶段管道/图遍历/LLM 驱动的工具调用。
  - **Mutability**：仅追加/整合/变异。
- **分析工具**：对每个 chat completion 和 embedding 请求打标（call type, source label, phase, timestamps），同步 GPU 计数器（DCGM 等），实现按阶段归因 token 量、功耗和延迟。
- **标准化做法**：保留各系统原生执行模型（如缓冲、并行摄入、跨块整合），统一生成 LLM 和嵌入模型，限制检索条目数（10 或 5），对对话型系统做最小提示适配。

## 3. 实验设计
### 数据集 / 场景
- **MemoryAgentBench (MAB)**：包含四个任务类别（准确检索、测试时学习、长程理解、选择性遗忘），共多个数据集（如 LongMemEval_S_*、EventQA、BANKING77、∞Bench-Sum 等），每个样本约 360K token 历史。
- **MemoryArena**：20 个多会话任务，每任务为一系列相互依赖的子任务，用于研究新鲜度-延迟权衡。

### Benchmark 对比方法
- 共评估 **10 个系统**，覆盖所有四个范式：
  - Paradigm I: long_context（全上下文基线）
  - Paradigm II: BM25、embedRAG
  - Paradigm III.a: GraphRAG、HippoRAG v2
  - Paradigm III.b: Mem0、SimpleMem
  - Paradigm IV: A-Mem、Letta、MIRIX

### 评估指标
- **准确性**：LLM-Judge Accuracy（基于 GPT-4o-mini 评判）。
- **系统指标**：构造延迟、查询延迟、能量（kJ）、GPU 利用率、存储足迹、token 成本、尾部延迟（p50/p95）等。

## 6. 论文的主要结论与发现
1. **构建成本主导智能体生命周期**：对于 LLM 中介系统，构建能量超过 300 次查询的总问答能量。能量每正确答案跨系统差异 >47×（BM25 4.1 kJ vs A-Mem 116 kJ）。
2. **构建负载是 embedding 和 prefill 主导**：构建阶段中解码 token 占比中位数仅 4.6%，大量工作集中于读取长块并输出紧凑记录，导致与延迟敏感的问答流量竞争 GPU 资源。
3. **嵌入流量按范式呈双峰形态**：Paradigm III.a 呈现大批量离线索引（如 GraphRAG 每批 ~2300 序列），而 Paradigm III.b 和 IV 是顺序的 1:1 调用-序列比，对嵌入服务器有不同需求。
4. **构造 LLM 下放受算法约束**：无硬性输出合同的系统（如 Mem0、SimpleMem）可平滑降级；有严格输出合同的系统（如 MIRIX）存在能力基线，低于则完全失效。
5. **无单一系统最优**：不同系统在构造成本、查询延迟和准确性之间占据不同位置。高查询量工作负载应选构造密集型系统，稀疏查询系统则选轻量构造系统。
6. **跨会话构造创建新鲜度-延迟权衡**：当单会话构造时间超过会话到达间隔时，同步调度阻塞查询，异步调度引入陈旧状态。每会话构造时间跨越五个数量级。
7. **每用户内存足迹和 token 成本增长斜率差异大**：1M token 下存储足迹差距约 9×；但 Paradigm IV 智能体系统的构建 token 成本随存储增长而超线性膨胀（Letta 在 256K+ 后急剧上升），成为长期部署的关键成本驱动因素。
8. **检索尾部延迟由算法边界决定**：固定深度管道（Paradigm II）p95/p50≈1.3×；LLM 驱动机器（如 GraphRAG、Letta）尾部可达 3.9×–5.9×，需外部迭代上限。

## 7. 优点
- **首创性**：首次对智能体内存进行系统级表征，填补了纯准确性评估与系统部署之间的空白。
- **系统化分类法**：四轴分类法为理解不同设计空间提供了清晰透镜，可用于预测未评估系统的行为。
- **全面的指标覆盖**：同时度量能量、延迟、存储、token 成本、GPU 利用率，而不仅限于准确率，使分析贴近真实部署决策。
- **可复现的工具**：阶段感知分析工具将开源，便于后续研究。
- **可操作的建议**：给出 10 条具体推荐（如构造调度、能力基线、摊销、新鲜度-延迟权衡等），对工程实践有直接指导意义。
- **公平对比**：统一了生成 LLM、嵌入模型、检索数量，并针对系统差异做最小调整，保留了各系统原生执行模型，避免扭曲行为。

## 8. 不足与局限
- **单节点单智能体**：实验仅在单 GPU 单智能体配置下进行，未涉及多节点或多智能体场景，而分布式部署会引入一致性、协调和网络开销等新问题。
- **未覆盖多模态记忆**：论文仅考虑文本形式；多模态记忆（图像、音频、结构化观测）将放大构造成本和存储复杂度。
- **基准偏差**：MemoryAgentBench 对回忆型任务（准确检索）权重较大，使得 BM25 在宏平均准确性上表现最佳，可能掩盖了结构增强系统在复杂推理任务上的优势（论文本身指出了此局限）。
- **遗忘策略缺失**：所有评估系统默认不进行显式遗忘或修剪，存储足迹单调增长；实际部署中需要独立遗忘策略，但论文未探讨。
- **硬件配置有限**：仅在一个 GPU 型号（H100）上测量，不同 GPU（如 A100、L40S）或不同部署架构（如多节点）可能改变结论的量化数值。
- **未考虑系统联合优化**：例如构造与 QA 共置 GPU 时的调度策略仅做初步讨论，未深入量化性能干扰或提出工程方案。
- **成本假设未包含模型服务开销**：能量成本仅考虑 GPU 能耗，未包括 CPU、内存、网络、存储 I/O 等其他系统组件。
