## 摘要
长期记忆对于LLM智能体在扩展交互中连贯推理、个性化回复以及复用过往经验至关重要。然而，现有的记忆增强方法通常将记忆视为固定资源：文本空间方法将检索到的记忆拼接进上下文窗口，导致大量token开销并对噪声证据敏感；而潜空间方法虽降低了文本成本，但仍依赖刚性检索或固定容量记忆接口。这造成了查询相关的记忆效用与固定记忆分配之间的不匹配。我们提出ElasticMem，一种学习将记忆作为弹性潜资源的记忆增强LLM框架。ElasticMem构建了一个包含检索键和内容缓存的离线潜记忆库，从推理器的隐藏状态中自适应检索记忆，通过习得的策略为每个检索到的记忆分配可变的潜预算，并选择性地注入潜状态作为软记忆token用于生成。整个记忆使用过程通过组相对策略优化利用下游任务奖励进行优化。我们在覆盖记忆密集型问答和具身智能体控制的MemorySuite上评估ElasticMem。在Qwen2.5-3B-Instruct和Qwen2.5-7B-Instruct骨干模型上，相比最强基线，ElasticMem分别将加权平均QA准确率提升了26.2%和24.6%，并将ALFWorld成功率分别提升了66.3%和27.2%，同时实现了最低的ALFWorld token消耗。消融实验和定性分析进一步表明，自适应检索和弹性预算分配帮助ElasticMem超越刚性余弦相似度，优先考虑有用证据和可迁移计划。我们的ElasticMem代码将在https://github.com/ulab-uiuc/ElasticMem发布。

## Abstract
Long-term memory is essential for LLM agents to reason coherently across extended interactions, personalize responses, and reuse past experience. However, existing memory-augmented methods typically treat memory as a fixed resource: text-space approaches concatenate retrieved memories into the context window, causing substantial token overhead and sensitivity to noisy evidence, while latent-space approaches reduce textual cost but still rely on rigid retrieval or fixed-capacity memory interfaces. This creates a mismatch between query-dependent memory utility and fixed memory allocation. We propose ElasticMem, a memory-augmented LLM framework that learns to use memory as an elastic latent resource. ElasticMem builds an offline latent memory bank with retrieval keys and content caches, retrieves memories adaptively from the reasoner's hidden state, assigns each retrieved memory a variable latent budget through a learned policy, and injects selected latent states as soft memory tokens for generation. The full memory-use process is optimized with downstream task rewards through group-relative policy optimization. We evaluate ElasticMem on MemorySuite, covering memory-intensive QA and embodied agent control. Across Qwen2.5-3B-Instruct and Qwen2.5-7B-Instruct backbones, ElasticMem improves weighted average QA accuracy by 26.2% and 24.6%, and improves ALFWorld success rate by 66.3% and 27.2%, respectively, over the strongest baselines, while achieving the lowest ALFWorld token cost. Ablations and qualitative analyses further show that adaptive retrieval and elastic budget allocation help ElasticMem prioritize useful evidence and transferable plans beyond rigid cosine similarity. Our code for ElasticMem will be released at https://github.com/ulab-uiuc/ElasticMem.

- **核心问题**：
  - **文本空间方法**（如MemoryBank、Mem0等）将记忆作为自然语言文本存储，检索后直接拼接到输入中，导致token开销巨大（尤其当记忆内容冗余时），且对噪声证据敏感。
  - **潜空间方法**（如AutoCompressor、MemGen等）虽通过连续向量压缩缓解token膨胀，但依然采用**固定容量接口**（每个检索到的记忆被分配相同数量的潜在表示）和**刚性相似度检索**（仅依赖固定编码器的余弦相似度），无法区分不同记忆对当前查询的实际效用。
  - 结果：记忆的效用是查询相关的，但现有系统却用固定规则决定记忆的**检索**和**容量分配**，造成严重不匹配。
- **研究含义**：该文认为应把记忆视为**可学习的弹性资源**，让模型学会根据下游任务需求调整检索哪些记忆以及为每条记忆分配多少表示容量，从而兼顾效率与准确性。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
ElasticMem通过学习实现**弹性潜记忆管理**：构建离线潜记忆库，基于推理器自身隐藏状态进行**查询条件式检索**，再通过一个轻量Transformer策略网络为每条检索到的记忆分配**可变的潜预算**（0到Bmax个潜token），最终将选中的记忆状态投影为软记忆token注入生成过程。整个流程（检索控制token、预算分配、投影、生成）通过**组相对策略优化（GRPO）**用下游任务奖励联合优化。

### 2.2 关键技术细节

1. **潜记忆库构建（离线）**：
   - 将记忆语料库M的每个块mi用冻结的基座LLM编码器fθ0编码，得到隐藏状态Hi。
   - 提取两个部分：
     - `ki = Hi[-1]`（最后一个隐藏状态）作为**检索键**。
     - `Ci = Hi[-Nc:]`（最后Nc个隐藏状态）作为**内容缓存**。
   - 记忆库B存储所有三元组(mi, ki, Ci)，构建后固定不变。

2. **查询条件式检索**：
   - 给定查询q，推理器先采样一个**检索控制token** `a ~ pθ(·|q)`，然后将q和a一起通过推理器获得查询状态 `hq = fθ(q,a)[-1]`。
   - 用余弦相似度 `si = cos(hq, ki)` 筛选出Top-Z个记忆块。

3. **弹性潜预算分配**：
   - 对每个检索到的块Ij，构造特征向量 `rj = Wr[hq; kIj; hq⊙kIj; sIj; ej]`（ej为排名嵌入）。
   - 将所有rj送入一个小型Transformer编码器 `πϕ`，输出各块的logits `ℓj`。
   - 从分类分布 `Cat(softmax(ℓj))` 中采样预算 `bj∈{0,...,Bmax}`（bj=0表示完全抑制该记忆）。
   - 策略πϕ不模仿余弦分数，而是通过下游奖励优化，从而学习将更大预算分配给真正有用的记忆。

4. **潜记忆注入**：
   - 根据预算bj，从缓存CIj中选取最后bj个状态：`eCj = CIj[-bj:]`。
   - 通过可学习的投影器 `Pψ`（两层MLP）将其映射回嵌入空间得到软token `Zj`。
   - 最终输入序列：`X = [E(q); E(a); Z1; ...; ZZ; E(u)]`（u为任务指令）。

5. **基于奖励的优化**：
   - 每个查询采样G条轨迹 `τg = (ag, Ig, bg, yg)`。
   - 计算任务奖励 `rg = R(yg, y*)`（如准确率、任务成功等）。
   - 用组相对优势归一化后，最小化裁剪后的GRPO目标函数，同时优化LoRA-adapted推理器θ、预算策略πϕ和投影器Pψ，记忆库B固定。

## 7. 优点

- **创新性**：首次将记忆使用建模为**可学习的弹性资源分配问题**，统一了检索控制和容量分配，端到端用强化学习优化，思想新颖。
- **实用性**：离线记忆库一次性构建，在线仅需一次前向通过推理器+轻量策略网络，推理效率高；同时显着降低了token消耗，适合实际部署。
- **系统性与完整性**：实验覆盖多种QA和具身任务，包含大量基线（8个文本+3个潜方法），消融实验设计严谨，定性分析提供了可解释性。
- **代码开源**（承诺）：便于复现和后续研究。

## 8. 不足与局限

- **模型通用性有限**：仅在Qwen2.5-3B/7B上验证，未在更大模型（如13B/70B）或其他架构上进行测试；分布外迁移至不同指令模型或其他任务类型（如网页浏览、代码交互）尚未考察。
- **记忆库静态**：目前记忆库是离线一次构建并冻结的，不随智能体经验积累更新，缺乏持续学习能力（作者也将其列为未来工作）。
- **任务范围局限**：QA任务为选择题格式，ALFWorld任务相对简单（不超过30步），未涉及更复杂的长程任务开放性环境（如SWE-bench、DiscoveryWorld等）。
- **消融实验仅在7B骨干上进行**：Figure 2中的消融未在3B骨干上重复，可能削弱结论通用性。
- **奖励信号简单**：目前仅用准确率或任务成功作为奖励，未引入过程奖励或中间步骤反馈，可能限制策略对记忆利用的细粒度学习。
- **Token计数方式有待明确**：软记忆token被计入消耗，但其实际计算代价是否完全反映在显存或时间上仍需厘清。
