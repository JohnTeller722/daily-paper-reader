## 摘要
近期针对大语言模型（LLM）智能体的基准测试主要评估推理、规划和执行能力。然而，记忆对智能体也至关重要，因为它使其能够随时间存储、更新和检索信息。这一能力尚未得到充分评估，主要是因为现有基准测试缺乏系统性的方法来评估记忆机制。本文从自我进化角度研究智能体记忆，并引入EvoMemBench，这是一个统一基准，沿两个维度组织：记忆范围（剧情内 vs. 跨剧情）和记忆内容（知识导向 vs. 执行导向）。我们采用标准化协议，比较了15种代表性记忆方法与强大的长上下文基线方法。结果表明，当前记忆系统仍远未达到通用解决方案：长上下文基线方法仍具高度竞争力；在当前上下文不足或任务困难时，记忆最有帮助；且没有单一记忆形式能在所有设置中保持一致性能。在知识密集型设置中，基于检索的方法仍然强劲；而在执行导向任务中，当程序性和长期记忆方法存储的经验与任务结构匹配时，它们更为有效。我们希望EvoMemBench能促进未来针对基于LLM的智能体的更有效记忆系统的研究。我们的代码可在https://github.com/DSAIL-Memory/EvoMemBench获取。

## Abstract
Recent benchmarks for Large Language Model (LLM) agents mainly evaluate reasoning, planning, and execution. However, memory is also essential for agents, as it enables them to store, update, and retrieve information over time. This ability remains under-evaluated, largely because existing benchmarks do not provide a systematic way to assess memory mechanisms. In this paper, we study agent memory from a self-evolving perspective and introduce EvoMemBench, a unified benchmark organized along two axes: memory scope (in-episode vs. cross-episode) and memory content (knowledge-oriented vs. execution-oriented). We compare 15 representative memory methods with strong long-context baselines under a standardized protocol. Results show that current memory systems are still far from a general solution: long-context baselines remain highly competitive, memory helps most when the current context is insufficient or tasks are difficult, and no single memory form works consistently across all settings. Retrieval-based methods remain strong for knowledge-intensive settings, whereas procedural and long-term memory methods are more effective for execution-oriented tasks when their stored experience matches the task structure. We hope EvoMemBench facilitates future research on more effective memory systems for LLM-based agents. Our code is available at https://github.com/DSAIL-Memory/EvoMemBench.

### 2. 论文提出的方法论：核心思想、关键技术细节

*   **核心思想**：提出一个统一的基准框架 **EvoMemBench**，该框架将智能体记忆的评估组织在 **两个维度** 上：
    1.  **记忆范围 (Memory Scope)**：区分 **剧情内 (In-Episode)** 和 **跨剧情 (Cross-Episode)** 的记忆演化。
    2.  **记忆内容 (Memory Content)**：区分 **知识导向 (Knowledge-oriented)** 和 **执行导向 (Execution-oriented)** 的记忆演化。
*   **关键技术细节 / 框架结构**：通过这两个维度的组合，形成了四个评估象限，覆盖了记忆的不同方面：
    *   **INEP-KNOW (In-Episode Knowledge Evolution)**：评估在单个对话或交互中，智能体能否保留和修正被提供的信息。例如，在对话中用户不断提供新信息，并改变先前陈述的事实，智能体需要准确记忆并修正。
    *   **INEP-EXEC (In-Episode Execution Evolution)**：评估在单个工具使用任务的执行过程中，智能体能否维护和更新任务相关的状态（如中间结果、对象引用）。该方法通过重构原始的多轮工具调用数据，增加了隐式引用（如用“我之前创建的目录”代替具体目录名），迫使智能体依赖记忆。
    *   **CROSS EP-KNOW (Cross-Episode Knowledge Evolution)**：评估智能体在多个共享同一背景的任务（池）中，能否积累可复用的知识（如领域事实、规则）。任务被按难度分为Easy, Medium, Hard三组。
    *   **CROSS EP-EXEC (Cross-Episode Execution Evolution)**：评估智能体能否从前序任务中提取可复用的执行经验（如动作流程、搜索策略），并应用到后续相似的任务中。该设置覆盖了三个领域：工具使用 (CROSS EP-TOOL)、网络搜索 (CROSS EP-WEB) 和具身智能体 (CROSS EP-EMB)。还进一步设计了跨环境迁移测试（如在Gorilla文件系统 [目标域]上评测从Vehicle Control[源域]学到的记忆）。
*   **Agent-Memory 交互形式化**：论文将智能体的记忆过程形式化为一个状态机。智能体在每个步骤 `t` 拥有一个记忆状态 `m_t`，其动作生成依赖于当前上下文和记忆状态 `a_t ~ π(·| history, observation, m_t)`, 并在收到反馈后通过函数 `U` 更新记忆 `m_{t+1} = U(m_t, observation, action, feedback)`。EvoMemBench测试的是不同记忆实现（即不同的 `π` 和 `U` 组合）的性能。

### 6. 论文的主要结论与发现

*   **发现1 (INEP-KNOW)**：强大的长上下文基线（如Gemini-3-Flash）仍然极具竞争力。
*   **发现2 (INEP-KNOW)**：当前记忆方法在**信息保留**上表现优于**信息修正**。记忆的瓶颈不仅在于检索相关证据，更在于决定何时更新或抑制旧信息。
*   **发现3 (INEP-EXEC)**：在**上下文预算受限**时，记忆的帮助最大（16K时提升14.5个百分点）。随着预算增加，边际收益减小，甚至可能引入噪声而损害性能。
*   **发现4 (INEP-EXEC)**：**程序性记忆**方法在执行任务中表现最强（如ReasoningBank, AWM），因为它们提供了可重用的执行指导。但压缩式的短期记忆方法可能因丢失细粒度执行细节而失败。
*   **发现5 (CROSS EP-KNOW)**：**任务越困难，记忆越有用**，但在简单任务上，记忆甚至可能有害（引入噪声或偏见）。
*   **发现6 (CROSS EP-KNOW)**：形成**可复用的知识**比单纯存储更多信息更重要。像ACE这种能有效应用知识的程序性记忆方法在困难任务上表现最好。
*   **发现7 (CROSS EP-EXEC)**：**不同执行领域青睐不同形式的记忆**。工具使用领域适合检索记忆，网络搜索适合通用长期记忆，具身智能体领域适合程序性记忆。
*   **发现8 (CROSS-EXEC Transfer)**：跨环境迁移的成功取决于记忆内容与**目标任务的决策过程是否匹配**。工具使用任务间的决策步骤相似，迁移更稳定；而具身任务执行条件差异大，迁移不稳定甚至产生负迁移。
*   **总的结论**：当前记忆系统远非通用解决方案。长上下文基线有竞争力；记忆在特定场景下（上下文不足、任务困难）有帮助；没有一种通用的记忆形式；检索方法适合知识密集型，程序性/长期记忆适合执行密集型。

*   **深入的分析与洞察**：论文不仅报告了最终的排名，还通过深入分析发现了多个具有启发性的“发现”，如“记忆在困难任务中更有用”、“记忆形式与任务结构不匹配时可能有害”、“跨环境迁移的局限性”等，这为设计下一代智能体记忆系统提供了宝贵的指导。
*   **开源与可复现性**：所有代码都已开源，严格遵循标准化评估协议，极大地促进了后续研究的复现和扩展。
*   **全面的效率分析**：除了任务性能（准确率/成功率），还系统性地报告了Token使用量和步数等效率指标，为在实际应用中选择记忆方案提供了成本维度的参考。

### 8. 不足与局限

*   **未评估记忆的训练或微调**：EvoMemBench 是一个推理时的评估基准，它专注于测试“使用”记忆的能力，而并未评估智能体**从交互中学习以优化其记忆机制**（即自我进化）的能力。所有被测试的记忆方法都是预设好的，不具备在线的参数调整能力。论文虽然标题含有“自我进化”，但基准本身并未直接衡量记忆系统“进化自身”的能力。
*   **长上下文基线在某些场景下的主导地位**：实验结果表明，在某些场景下（如带足够上下文的INEP-KNOW），强大的长上下文模型比任何外部记忆方法表现都好。这提出了一个根本性问题：当未来模型上下文窗口无限大时，外部记忆是否还有必要？当前的EvoMemBench基准可能未能充分捕捉外部记忆系统在效率和知识管理上的长期优势。
*   **跨环境迁移设置的局限性**：迁移实验的设计（在一个子集上训练，在另一个子集上评估）非常直接。实际应用中可能存在更复杂的跨域、跨任务、甚至是零样本的迁移场景。基准未涵盖这些更高级的记忆泛化能力。
*   **对记忆内容的定义可能过于简化**：“知识”和“执行”虽然是一个好的起点，但智能体在实际任务中可能需要更复杂的记忆，如“社交记忆”（用户偏好、情绪）、“情景记忆”（特定时间、地点的事件）等，这些类别在当前基准中可能没有得到充分体现。
